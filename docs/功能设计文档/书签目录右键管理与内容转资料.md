# 书签目录右键管理与内容转资料 · 功能设计

> 状态：已交付（2026-11-24）· 关联决策 D89（决策记录）
> 范围：`apps/web`（管理台书签页）、`apps/server`（organize / pipeline / materials 路由）、`apps/web/src/lib/mock.ts`
> 前置阅读：AGENTS.md 红线、D27（act+undo）、D52（书签行右键）、D61/D64/D65（资料库）、D70（书签/资料分流）、D76（目录语义上下文）、D77（分类自检）、D81/D82（实时刷新与目录搬家）

## 1. 背景与目标

当前管理台书签页只有**书签行**支持右键（D52：打开原页/编辑/移动/置顶/归档/复制/删除），目录树只能靠行尾 hover 小图标（新建/重命名/搬家/删空目录），且缺少"以目录为单位"的批量智能操作。用户提出四项需求：

1. **目录右键管理**：目录树行也要有右键菜单，操作集中、可发现性更好。
2. **目录内重新分类整理**：对某个目录（含子目录）的书签做一次 AI 重新归位，而不是只能全库重分类。
3. **内容页书签自动转资料**：目录内属于内容页（文章/教程/文档/报告）的书签自动抓正文入资料库；**提取失败的书签要给出"建议丢弃"清单**（用户 2026-11-23 补充）。
4. **正常状态角标**：正常书签改为名称/favicon 左上角一个低调角标，减少满屏"正常"文字噪音（用户 2026-11-23 补充）。

非目标：

- 不做文件夹拖拽（D81 已定：搬家走弹窗，树上的拖放只服务"书签拖入目录"）。
- 不引入 shadcn `context-menu` 新依赖（沿用 D52 手写轻量浮层，零新增依赖）。
- 不做后台常驻的全库资料扫描；本次是**用户显式发起、可中止**的目录级任务。
- 不做自动删除（红线③）：失败清单只出建议，归档/删除均由用户确认。

## 3. 交互设计

### 3.1 目录右键菜单

在目录树真实目录行、收纳盒行挂 `onContextMenu`（Ctrl+点击放行原生菜单，同 D52）。菜单浮层复用 D52 结构（`min-w-[180px]`、视口钳制、mousedown 拦截、Esc/resize 关闭）。打开期间计入 D82 `blocked`，后台刷新不替换树。

**普通目录菜单项**（`folderCtx`）：

| 菜单项 | 图标 | 条件 | 行为 |
| --- | --- | --- | --- |
| 打开目录 | ChevronRight | 恒有 | `selectFolder(id)` |
| 新建子目录 | FolderPlus | 恒有 | 展开父级 + 行内 `InlineInput` |
| 重命名 | Pencil | 恒有 | 行内重命名（同双击） |
| 移动到… | FolderInput | 恒有 | 打开目录搬家弹窗（复用同一 Dialog，含"根级"） |
| AI 重新整理此目录 | Sparkles | 恒有 | `POST /organize/folder`，busy 态 + 结果 toast + 刷新树/列表 |
| 提取资料 | BookMarked | 恒有（无书签时禁用） | 打开资料提取弹窗（SSE 进度） |
| ─── | | | |
| 删除目录… | Trash2（红） | 恒有 | 二次确认：非空提示"将连同 N 条书签与子目录一起删除"（服务端 `deleteFolderTree`，D73） |

**收纳盒行菜单**：打开收纳盒 / AI 归位（复用 `processInbox`）。

**「全部书签」行**：不设右键（全库重分类已有树底部入口，避免语义混淆）。

删除确认从"仅空目录可删"变为**所有目录可删 + 显式确认**：确认文案给出 `totalCount`，删除走既有 `DELETE /folders/:id`（服务端已是树删）。未做改动时不引入新的批量删除入口。

### 3.2 目录内 AI 重新整理

**语义（与全库重整理的区别）**：范围 = 该目录及其子目录下的全部书签；**目标目录限定在该子树内**（现有子目录 + 允许 AI 在**该目录下**新建子目录）。永不把书签移到子树外，永不删除、不归档。

- 理由：目录级操作必须是"在这个目录里整理"，移出目录会破坏用户对该目录的预期；跨目录调整仍走全库重分类。
- 归类证据：目录完整路径 + 代表书签（D76 `folderSampleTitles`），禁止仅凭目录名猜语义。
- 生效方式：D27 直接生效 + `organize_version` 整批可撤销；冲突项（计划后被用户改动/删除/隐私规则变化）跳过并计数。
- 交互：菜单点击即执行（无确认流），执行中菜单项显示加载态、完成后 toast「已重新整理 N 项（版本历史可撤销）」，树与列表刷新。
- 无 LLM：只跑规则引擎（domain_map 命中项），其余不动，结果说明"未配置模型，仅应用规则分类"。

### 3.3 内容页书签 → 资料（含失败建议丢弃）

**入口**：目录右键「提取资料」→ `MaterialScanDialog`。

**识别与提取流程**（每条）：

1. 私密 / 隐私域名 → `skipped`，不抓取、不入库（红线②）。
2. 已有 active 资料 → 直接排除出候选（不重复抓、不占单次配额）。
3. 视频/图片（URL 规则）→ 直接物化（视频不下载本体）→ `created`。
4. 其余（article 候选）→ `crawlOne` 补抓正文：
   - 抓取失败（HTTP/网络/超时）→ `failed`，原因落 `cache.fail_reason` → **进入建议丢弃清单**。
   - 抓到但正文 < 200 字 → `not_content`（不像内容页，书签保持不动，不进丢弃清单）。
   - 正文 ≥ 200 字 → 内容判定：
     - 有 LLM：按批（≤10 条/次）用小段正文做「是否内容型页面（文章/教程/文档/报告）」判定，true → 物化 + `created`，false → `not_content`。
     - 无 LLM：规则兜底，正文 ≥ 800 字视为内容页 → `created`，否则 `not_content`。
5. 单次运行上限默认 **30 条**（钳制 1–60），剩余条数返回，弹窗显示「继续扫描剩余 N 条」。
6. 全程串行、可中止（关闭弹窗/点"停止"即 abort，服务端断开即停，D62 规范③）；每处理一条推送一条 SSE 事件。

**建议丢弃清单**：

- 只包含 `failed` 条目（标题 + 失败原因 + 原链接）。
- 默认全选，两个动作：
  - **归档所选（推荐）**：`PATCH /bookmarks/:id {status:'archived'}`，软归档可恢复。
  - **删除所选…**：二次确认后逐条 `DELETE`（不可恢复；红色危险按钮）。
- 关闭弹窗不执行任何操作；**系统永不自动归档/删除**（红线③）。
- 失败原因做人类可读映射：`crawl_failed:HTTP 404` → 「页面打不开（404）」、超时 → 「抓取超时」、其余 → 「抓取失败」。

### 3.4 正常状态角标

- 正常书签：**移除右侧「正常」文字徽章**，改为 favicon 图标左上角一个 6px 绿点（`ring-2 ring-background` 分隔），`title="正常"`；favicon 未就绪时角标挂在字母占位块同一位置。
- 失效 / 疑似 / 已归档：右侧徽章保持现状（红/琥珀/灰），仍是最醒目的信号。
- 失效视图的分组头（打不开/疑似失效）不变。

## 4. 接口设计

### 4.1 `POST /api/v1/organize/folder`

```jsonc
// request
{ "folderId": "f-xxx", "includeSubfolders": true }
// response（OrganizeRunResult 同形）
{
  "sessionId": "...", "status": "applied", "answer": "共扫描 42 条…",
  "actions": [{ "type": "move", "bookmarkTitle": "...", "fromFolder": "A04", "toFolder": "A05" }],
  "versionId": "...", "applied": 7, "conflicts": []
}
```

- 错误：目录不存在 `404 folder_not_found`；扫描上限 500 条（超出只处理前 500 并在 answer 说明）。
- 权限：随 `/api/v1` 鉴权；隐私条目/私密书签不送模型、不移动。
- 副作用：写 `organize_session` + `organize_version`；`bookmark.organized` webhook（聚合计数）。

### 4.2 `GET /api/v1/materials/scan/stream?folderId=&includeSubfolders=1&limit=30`

SSE 事件：

```
event: start   data: { total }                         // 本次处理的候选条数
event: item    data: { id, title, status, reason? }     // status: created|not_content|failed
event: done    data: { total, processed, created, notContent, skipped, failed: [{id,title,url,reason}], remaining }
event: error   data: { error }
```

- `includeSubfolders=1` 时范围含全部后代目录；`limit` 钳制 10–60。
- 客户端断开（`stream.aborted`）→ 停止后续抓取，已入库结果保留（幂等）。
- 隐私条目永不抓取；多租户上下文在流内以 `runAsUser` 固定（D67）。

## 5. 数据与一致性

- **无新表、无迁移**（复用 `organize_version` / `material` / `content_cache`）。
- 资料物化幂等：`upsertMaterial` 覆盖式，重复扫描不产生重复条目；`dismissed` 条目不复活（既有语义）。
- 目录重整理的目标：
  - 现有目录：动作携带 `plannedFolderId`（稳定 ID），提交时按 ID 解析（不受同名影响）。
  - 新建子目录：`createFolder` 动作携带 `parentFolderId`，提交时在该父级下 find-or-create。
- 撤销：逆放 move + 删除 AI 新建的空目录（既有 `rollback` 语义，无需改动）。
- 浏览器同步：move 经既有镜像入队（`enqueueMirrorMoves`）收敛到收藏夹；新建子目录同步由既有 sync 引擎的目录收敛负责。

## 6. 异步与性能（D62）

| 任务 | 判据 | 实现 |
| --- | --- | --- |
| 目录重整理 | 用户显式发起 + 有结果反馈，允许同步等待 | 同步请求内完成；受 500 条上限约束 |
| 资料扫描 | 用户显式发起、耗时长 | SSE 逐条进度 + 断开即停 + 单次 30 条上限 + 串行抓取（天然并发闸 ≤1）+ 失败落 `fail_reason` |

不新增常驻定时器；不引入后台队列。

## 7. 红线校验

- ① NAS 资源：无新依赖、无新常驻任务；服务端 bundle 增量可忽略。
- ② 隐私：抓取/模型调用前均经 `serverDecide`（`server_fetch` / `call_model`）；私密/隐私域条目 `skipped`，不入资料、不移动、不送模型。
- ③ 删除：目录删除需二次确认；失败书签只出「建议丢弃」，归档/删除均用户确认。
- ④ 版权：资料沿用现状（仅本地私有库，公开导航站不投影）。
- ⑤ 导入：不涉及。

## 8. 验收标准

1. 目录行右键出现菜单；所有菜单项可用；收纳盒行右键只有"打开/AI 归位"；打开菜单时后台刷新不替换树。
2. 目录重整理：只影响该子树；新建子目录建在该目录下；版本历史可撤销；无 LLM 时不报错且说明规则结果。
3. 资料扫描：SSE 进度可见、可停止；成功条目出现在资料页；失败条目进入建议丢弃清单并可归档/删除；隐私条目永不出现。
4. 正常书签只显示 favicon 左上角绿点，无「正常」文字；失效/疑似/已归档徽章不变。
5. `?mock` 演示模式可完整走通四类交互（无需真实服务端）。
6. 服务端集成测试 + web typecheck/build 全绿；既有 E2E 书签相关用例不回归。

**复核整改（2026-11-24 code review）**：P1——目录级 `ensureFolder`/apply 复用只查直接子级，模型返回孙级同名目录会重复建（已改为子树任意深度复用，补回归）；P2——删死 `sessionId`、`subtreeIds.includes` 改 Set、补归档排除回归；P3——D83→D89 注释、`pathOf` 环守卫、扫描「停止」态文案与 remaining 估算、`moveFolderTo` 拦 mock error、SSE 抽 `lib/sse.ts` 共用、`folderIds` 截断 warn。整改后 server 302 全绿。

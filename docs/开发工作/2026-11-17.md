## 1. 本轮目标与边界

本轮不再以功能数量为目标，优先交付一个：

**扩展 + 单用户 Docker 自建端，数据可信、核心任务可用、别人能够独立安装和恢复的版本。**

### 1.1 当前交付范围

- 浏览器扩展；
- 单用户 Docker 自建端；
- 收藏、搜索找回、整理预览/撤销、快照、备份恢复五条核心任务链；
- 新标签页作为入口之一，不强制用户启用；
- AI 是基础体验的增强项，不是导入、浏览、搜索的前置条件。

### 1.2 当前明确不做

- 完整纯本地模式；
- 官方云端 SaaS 上线；
- 完整双向浏览器书签同步；
- 新模板、模板商城、公开广场；
- 多 Agent、通用知识库聊天；
- 大批量新增模型供应商；
- 微服务、Redis、复杂推荐和远程分析平台。

已有功能不因暂缓而随意删除；不成熟能力应标记为实验性或默认关闭。

### 1.3 优先级说明

- **P0：发布阻断**。涉及隐私、数据安全、一致性、未授权访问，必须关闭。
- **P1：核心自用**。决定产品是否值得持续用于真实任务。
- **P2：发布必需**。保证新用户能够独立安装、恢复和反馈。

# 持续质量线：贯穿所有阶段

## QA-1：确定性回归

每次相关修改运行：

- [ ] 单元测试。
- [ ] API 集成测试。
- [ ] mock LLM 失败处理。
- [ ] 隐私与网络安全测试。
- [ ] 数据事务、幂等和恢复测试。
- [ ] 相关真实浏览器/E2E 场景。

## QA-2：真实模型质量抽查

按需执行，不要求每次提交消耗真实 API：

- [ ] 使用固定脱敏样本。
- [ ] 记录模型名称和版本。
- [ ] 记录输入来源、成本和结果差异。
- [ ] 比较规则版与内容版。
- [ ] 不将 mock 通过写成真实分类质量达标。
- [ ] 没有明显改善时先检查输入质量和策略，不继续叠加 Agent。

## QA-3：真实自用记录

每次遇到明显问题只记录：

1. 当时要完成什么？
2. 哪里卡住、改用什么办法？
3. 是否愿意下次继续用？

每轮真实使用或反馈回看只输出三个结论：

- 继续什么；
- 修复什么；
- 暂不做什么。

样本少时记录事实，不给百分比强加普遍意义；单条新功能建议先记录场景，不直接实现。

## QA-4：反馈优先级

- 数据丢失、泄露或无法恢复：立即停止相关自动动作，作为发布阻断修复。
- 自己真实任务反复卡在同一步：优先修复，不等待更多用户投票。
- 多次独立反馈同一阻碍：提升优先级，先找共同根因。
- 用户导入后不再回来：检查找回价值、安装成本和入口，不先加通知。
- 用户持续找回但不用主页：保留资料库方向，不强推新标签页。

## 1. 产品定位

### 1.1 一句话定位

**当你收藏了几百个网址却再也没打开过它们时，my-favorites 用 AI 把这堆书签变成一个能天天用的个人导航主页。**

### 1.2 唯一核心任务（JTBD）

用户雇佣本产品只做一件事：**"把我失控的书签堆，变成我有掌控感的、每天使用的入口。"**

由此推导出产品各部分的角色：

| 部分 | 角色 | 定性 |
|---|---|---|
| AI 聊天整理 + 内容缓存 | **楔子**（用户为什么选我们而不是别的书签工具） | 核心 |
| 导航站生成 | **产出物**（整理结果的可视化落地，也是日活阵地） | 核心 |
| 一键收藏/自动分类 | **留存钩子**（让 AI 介入每一次新的收藏） | 核心 |
| 定期死链/查重维护 | **回访理由** + 信任构建 | P1 |
| 多端同步、私密书签、模板商城 | 服务于闭环的配套 | P2，坚决后置 |

**判断标准**：任何新功能提案，必须能回答"它让整理更准、让导航站更有用、或让用户更常回来"三者之一，否则不进路线图。

### 1.3 为什么不是 Raindrop.io（竞争壁垒声明）

Raindrop.io 是最强书签管理器（集合、建议、死链检测、永久快照），但它是**管理工具**：产出是"一个更好的书签库"，用户依然要自己动手整理。我们：

1. 产出物不同——我们落地为**每天实际使用的导航主页**（占据新标签页），Raindrop 的产出没人每天看；
2. 交互范式不同——我们以**聊天指令 + 内容理解**完成整理（"把开发文件夹里 2023 年以前的链接按内容重新分类"），Raindrop 是手动为主+被动建议；
3. 数据资产复利——缓存的内容摘要/快照随时间越积越多，整理偏好持续学习用户习惯，**用得越久越准**，形成切换成本。

## 2. 竞品分析

### 2.1 第一梯队（直接竞对）

**Raindrop.io**（百万级用户，成熟商业产品）
- 强项：全平台、集合/嵌套标签、死链检测（付费）、永久副本（付费）、公开集合、AI 建议分类
- 弱项（我们的机会）：整理以手动为主；无导航站产出；无聊天式整理；云托管不可自建
- **对我们的启示**：死链检测/快照是"付费级价值"已被验证，可放心投入；但其 AI 建议是"推荐你确认"而非"对话式执行"，交互代差是我们的窗口期

**Flomo / Cubox 类内容收藏**：收藏对象是"内容片段"而非"网址入口"，与本产品 JTBD 不同，不构成直接竞争，但验证了"AI 辅助整理"的付费意愿。

### 2.2 Edge 商店参考扩展（v0.1 已析，摘要保留）

| 扩展 | 核心功能 | 借鉴 | 短板 |

## 3. 用户画像与旅程

### 3.1 核心画像（M1 只服务前两个）

- **P1 失控的收藏者**（主力）：书签 200–2000 条，多文件夹堆砌，"存了=学会/用到"的心理安慰，实际从不回访。痛点：找不到、不敢删、没面子。付费意愿：中。
- **P2 效率门户用户**：想要美观的个人起始页，书签是素材库。痛点：手工建导航站太费时。付费意愿：高（愿为主页美化/模板付费）。
- **P3 自托管极客/NAS 用户**：数据主权敏感。付费意愿：低（倾向买断/自建），但是口碑传播节点与自建方案的验证者。

### 3.2 用户旅程与 Aha Moment

```
安装扩展 → 一键导入全部书签（30 秒，无需任何配置）
   → AI 后台抓取内容并整理（用户可离开）
   → 3 分钟后回来：看到 diff 预览 → 一键采纳
   → 生成个人导航站 → 设为新标签页      ← ★ Aha Moment
   → 此后每次收藏自动归位、每周收到维护报告
```

**Aha 定义**：导入后 10 分钟内，用户看到自己书签被整理并生成导航站。全程无需注册、无需配 API Key（M1 提供免费试用额度）——**注册和 BYOK 都必须放在 Aha 之后**，这是激活率的生命线。

## 4. 核心体验闭环（留存引擎，v0.1 缺失章节）

```
        ┌─ ① 收藏钩子：每次一键收藏，AI 即时建议归位（<1s 展示，不阻塞）
日活 ←──┤  ② 新标签页：导航站就是起始页，每天天然曝光
        └─ ③ 周报钩子：每周维护报告（死链 N 条、重复 M 条、本周新增归档）
                      → 用户点进处理 → 再次体验 AI 能力
```

三个钩子分别解决"每天回来（②）""每次使用有 AI 参与（①）""每周有理由打开管理界面（③）"。**M1 至少交付 ② + ①**。

## 5. 功能架构

```
┌────────────────────────────────────────────────────┐
│                浏览器扩展（用户唯一入口）             │
│  收藏按钮 · 侧栏聊天整理 · 新标签页(导航站) · 周报角标 │
└──────────────┬─────────────────────────────────────┘
               │ 同一套 API
┌──────────────▼─────────────────────────────────────┐
│      服务端：官方云（SaaS） ≡ 自建服务端（Docker）    │
│  · 书签/目录服务        · 内容缓存引擎（双通道↓）     │
│  · AI 整理编排（LLM）   · 导航站生成与托管            │
│  · 定时维护调度         · 同步与账号                 │
└────────────────────────────────────────────────────┘
```

### 5.1 内容缓存引擎 —— 双通道设计（v0.1 的重大修订）

| 通道 | 触发 | 覆盖 | 说明 |
|---|---|---|---|
| **A. 扩展端就地捕获（主）** | 用户收藏瞬间，人就在页面上 | 登录墙✅ 内网✅ 反爬✅ | 扩展在当前标签页提取正文（Readability），随书签一起提交；质量最高、零额外抓取 |
| B. 服务端补漏抓取 | 导入存量书签 / 周期刷新 | 公开页 | 队列限速、robots 尊重；失败降级为"仅元数据" |

存量导入的大批量抓取仍需服务端（或自建端）执行，所以 B 通道不可省，但 A 通道决定了"新收藏"的内容质量与隐私故事：**用户正在看的页面内容，由用户自己的浏览器捕获，而不是被云端爬虫重新爬一遍。**

缓存分级不变：L1 摘要+标签（AI）→ L2 正文文本 → L3 净化 HTML 快照（云端默认只存 L1+L2，L3 可选/自建端不限，见 §8 成本）。

## 6. 功能模块（带优先级标注）

优先级：**P0** = M1 必须；**P1** = M2；**P2** = M3/远期。

### F1 书签获取与管理
- **F1.1 [P0]** 一键导入浏览器全部书签（保留目录结构与时间）；Netscape HTML 文件导入
- **F1.2 [P0]** 一键收藏（快捷键/右键），**提交时扩展端就地捕获内容**（§5.1 通道 A）
- **F1.3 [P0]** 树形目录管理
- **F1.4 [P0]** 收藏时 AI 即时建议归位（点选确认，<1s）——留存钩子①
- **F1.5 [P2]** 多端同步（官方账号或自建端）
- **F1.6 [P0]** 导入导出：JSON 全量备份 / Netscape 导出（数据可迁移承诺）
- **F1.7 [P2]** 私密书签二次验证 —— *从 M2 下调：不服务核心闭环*
- **F1.8 [P2]** 常用/备用分层归档

### F2 内容缓存引擎
- **F2.1 [P0]** 扩展端正文捕获（Readability）：正文/标题/描述/og:image/favicon
- **F2.2 [P0]** 服务端补漏抓取队列：限速、重试、robots、失败标记（反爬/登录墙/超时）
- **F2.3 [P0]** L1 摘要生成（AI）+ 关键词/标签
- **F2.4 [P1]** L3 净化 HTML 快照（云端可选付费、自建端默认开启）
- **F2.5 [P0]** 隐私域名排除清单：名单内只存 URL 不抓内容、不送 AI
- **F2.6 [P2]** embedding 向量索引（语义搜索前置）

### F3 AI 聊天整理（核心）
- **F3.1 [P0]** 对话入口（扩展侧栏）
- **F3.2 [P0]** 自然语言圈定范围："把开发文件夹 2023 年前的链接按内容重新分类"
- **F3.3 [P0]** 整理原子操作：自动分类（基于缓存正文而非标题）/ 改名与摘要 / 合并重复 / 新建目录结构 / 建议删除项
- **F3.4 [P0]** **diff 预览 → 确认 → 应用**，绝不静默改动
- **F3.5 [P0]** 整理快照版本，一键撤销
- **F3.6 [P1]** BYOK：OpenAI / Anthropic / Ollama / OpenAI 兼容端点
- **F3.7 [P1]** 整理报告（移动/合并/死链统计）
- **F3.8 [P1]** **整理偏好记忆**：记住用户的分类习惯与命名风格，越用越准（壁垒功能，M2 起）
- **F3.9 [P0]** **成本保护的大规模整理策略**：千级书签不做逐条 LLM 分类——先 embedding 聚类 → LLM 只为聚类命名与边界调整 → 逐条归属（成本从 O(n) 次大调用降为 O(√n)+n 次轻调用）

### F4 导航站生成
- **F4.1 [P0]** 一键生成导航站（M1 仅 1 套模板：经典宫格式，含主题色/深浅色变体）
- **F4.2 [P1]** 模板扩充：极简清单式、卡片瀑布流式、个人主页式（共 4 套）
- **F4.3 [P0]** 搜索框（本地书签搜索 + 可选外部引擎）、分组折叠、响应式
- **F4.4 [P0]** 设为新标签页（**留存钩子②，M1 必须**）
- **F4.5 [P1]** 发布控制：私有 / 随机链接公开 / 密码访问（公开页内容合规审核见 §9）
- **F4.6 [P1]** 导航卡片联动缓存：图标/封面/摘要；死链自动打标或隐藏
- **F4.7 [P2]** 模板 DSL + 自定义 CSS

### F5 定期维护
- **F5.1 [P1]** 死链检测：默认每周、可配；HTTP+重定向+重试；**三级判定：确认失效 / 疑似失效(反爬·仅标注) / 正常**；处置动作：归档/删除/换链（"AI 找替代站点"为 P2）
- **F5.2 [P1]** 查重：URL 规范化（去 tracking 参数、统一协议与末斜杠）+ 同域同名相似检测 → 合并建议，确认后执行
- **F5.3 [P1]** 内容变更检测与摘要刷新
- **F5.4 [P0→P1]** 调度：云端统一调度 / 自建端内置 cron —— *随 M2 云端一起交付*
- **F5.5 [P1]** 维护周报通知（扩展角标 + 站内）—— **留存钩子③**
- **F5.6 [P2]** AI 推荐替代站点

### F6 部署形态
- **F6.1 [P1]** 官方云端 SaaS：**M1 用免费试用额度支撑 Aha，正式商业化在 M2**
- **F6.2 [M3]** 自建服务端：单 Docker 镜像 + compose 文件，Web 管理台，内置调度，支持 Ollama/任意 OpenAI 兼容端点实现全离线；自动备份到指定目录；云端↔自建迁移工具
- **F6.3 [P0]** 本地模式：无服务端时扩展本地 IndexedDB 提供收藏/分类/快照/搜索，AI 走 BYOK 直连，导航站导出为静态 HTML
- **F6.4 [P2]** 极简"自建 lite"：仅维护任务+导航托管的最小镜像（为 NAS 圈子做传播钩子）

### F7 搜索与浏览
- **F7.1 [P0]** 全文搜索：标题/URL/备注/缓存正文
- **F7.2 [P2]** 语义搜索
- **F7.3 [P1]** 筛选器：分类/标签/时间/状态/频率，可存预设
- **F7.4 [P0]** 网格/列表、深浅色、中英 i18n

## 7. 商业模式与成本（v0.1 缺失章节）

### 7.1 收费结构

| 层 | 定价 | 内容 |
|---|---|---|
| Free | ¥0 | 收藏/整理/导航站基础能力；**AI 整理走 BYOK 完全免费**；云端 L1+L2 缓存配额（如 500 条）；每月 1 次维护任务 |
| Pro（订阅） | ¥15–25/月 或 ¥128/年 | 无 BYOK 也能用 AI（平台承担 token）；快照存储配额；每周自动维护；历史版本无限；公开导航站 |
| 自建 | 免费开源核心 / 一次性买断 Pro 镜像（待定） | 全功能，数据与 AI 成本全自持 |

**原则：BYOK 用户永远有完全免费的完整体验**——这既是成本护城河（AI 成本转嫁），也是与 HamHome 一致的极客圈口碑策略。

### 7.2 成本红线

- **存储是最大隐性成本**：云端默认只存 L1（摘要）+ L2（正文文本），不存 L3 快照；Pro 的快照配额上限（如 2GB）；正文截断（如 20KB/条）
- 大规模整理走 §6 F3.9 的聚类策略，单用户全库整理 token 成本控制在 < ¥0.5 量级
- 服务端抓取队列限速，避免带宽成本失控

## 8. 成功指标（v0.1 缺失章节）

**North Star：周活跃导航站（本周至少 3 天通过导航站/新标签页访问书签的用户数）**——它同时证明"整理有效"和"产出物被日常使用"。

| 阶段 | 指标 | 目标（首发后 3 个月） |
|---|---|---|
| 激活 | 导入→Aha 转化率（10 分钟内完成整理+生成导航站） | ≥ 40% |
| 激活 | Aha 中"设为新标签页"比例 | ≥ 25% |
| 质量 | diff 采纳率（用户确认应用的比例） | ≥ 70%，低于此说明整理质量不过关 |
| 留存 | W4 留存 | ≥ 20% |
| 留存 | 周报点击率 | ≥ 30% |
| 口碑 | 自建镜像拉取量（开发者圈传播指标） | 监测即可 |

## 9. 风险与合规（v0.1 缺失章节）

| 风险 | 等级 | 对策 |
|---|---|---|
| 商店审核：读取全部书签+网络抓取属高敏权限 | 高 | 权限最小化（按需申请 bookmarks）、上架说明页充分披露隐私设计；Edge/Chrome 双提审，Edge 先行 |
| 抓取与快照的版权问题 | 中 | 快照仅用户私有可见（公开导航站只展示元数据+摘要，不展示快照正文）；robots 尊重；提供"仅元数据"开关 |
| 云端处理的隐私悖论（自建用户不信任云） | 中 | 明确数据边界：云端仅处理用户显式同步的内容；维护任务在自建端本地执行；隐私域名清单默认内置常见敏感域（银行/内网段） |
| 公开导航站被滥用（引流站/违规内容） | 中 | 公开分享默认审核敏感词+举报入口；M1 只做随机链接不公开检索（v0.1 决策维持） |
| 死链误判伤信任 | 中 | 三级判定+保守策略：疑似失效只标注不处置；周报措辞用"建议"而非"已删除" |
| LLM 整理质量翻车（错分类） | 中 | diff 确认+版本回滚兜底；整理报告让用户看到全貌；采纳率作为核心质量指标持续监控 |
| token/存储成本失控 | 中 | §7.2 红线；BYOK 优先；配额硬限 |

## 11. 决策记录

### 已定决策（PM 拍板，附理由）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **扩展先行**，不做独立 Web 应用起步 | 书签的源头在浏览器；扩展导入是零摩擦路径，且新标签页阵地只有扩展能占据；独立 Web 起步则激活漏斗第一步就是"导出书签文件"，流失极高 |
| D2 | AI 用量 **BYOK 优先**，SaaS 代付型 Pro 后置（M2） | M1 无商业化压力，token 成本零化；同时 BYOK 是极客圈的信任信号 |
| D3 | 死链采用**保守三级判定**，疑似失效只标注 | 误删用户数据的信任损失不可逆；标注-观察周期能自然过滤反爬误判 |
| D4 | 云端默认不存 L3 快照，只存摘要+正文文本 | 存储成本红线（§7.2）；快照价值主要在"防失效回看"，付费/自建场景再开 |
| D5 | 公开导航站 **M1 仅随机链接分享，不做公开广场** | 合规成本与冷启动价值不成比例 |
| D6 | 首发 Edge + Chrome 双上架，Edge 优先提审 | 参考竞品均在 Edge 生态；Chrome 量更大，双端 Manifest V3 代码基本同源 |

# 新标签页小组件（Widget）方案 v0.3

> 2026-11-20 起草。背景：D40 新标签页收敛为「品牌标 + 搜索 + 最常访问」后，用户提出把页面做成**组件化**设计——官方内置若干实用小组件，用户自选启用。首批三件：**公网 IP、天气、黄历**（用户自述高频使用）。
> 本文所有外部端点均经本机实测（国内直连网络，2026-11-20），非纸面调研。
> **v0.2 用户拍板（2026-11-20）：用户可控制的只有「显示 / 隐藏」**——砍掉全部 per-widget 设置项（城市输入、归属地开关、排序拖拽）。推论：天气城市**自动定位**（IP 归属地解析，无用户输入），展示内容固定，自定义面板只增一行开关 chips。Q1–Q5 决议见 §6。
> **v0.3 视觉修订（2026-11-20 用户反馈「传统卡片样式太俗，要和页面融为一体」）**：废弃卡片盒子（CardShell/网格卡带全删），改为**内联融入页面既有字层**——天气并进时钟区日期行（详情收进 hover）、黄历作日期下两行小字、IP 作页脚状态行。数据层（缓存/回退链/自动定位）不变。
> **v0.3.1 走查修订（2026-11-20 二轮反馈）**：① **修复 IP「IPv6 粘滞」**——旧版按序探测、首个成功即停：v6 优先网络下一旦 IPv6 先返回并被缓存 24h，可达的 IPv4 源永远被跳过、强刷也回不去；改为**全源并行探测 + 择优**（IPv4+归属 fast path 拿到即返回不陪慢源等超时）。② **黄历压成两档字阶**（「文字太多容易分散视觉」）：主行=农历日（text-sm 深一档，有节气/节日优先于干支年）、辅行=宜/忌各 2 项（11px 更淡），砍掉堆料式平铺小字。
> **v0.3.5 宜忌分色（五轮反馈「宜和忌做个区分显示」）**：黄历行三段横排——`农历十月十二`（中性）｜`宜 ××`（绿 80%）｜`忌 ××`（红 70%），低饱和语义色与产品语义色族同构（绿正向/红负向），是新标签页首处彩色。**v0.3.6 用色收束（用户定样）**：着色范围收窄到**仅「宜」「忌」两个字**，农历日与宜忌条目全部保持中性灰——色只标吉凶语义，不给内容上色。附加区原则不变：仍只有一行。
> **v0.3.4 减载修订（四轮反馈「内容有点多，还是别扭」）**：四行压两行——行1=黄历内容单行（`农历十月十二 · 宜 合帐 裁衣 · 忌 置产 造船`，12px 略深）、行2=环境状态行（`怀化 ☀️ 16° · 223.149.24.85`，11px 更淡，天气与 IP 合一行）；**次级信息一律退 hover**：干支生肖/冲煞/宜忌全量 → 黄历 title；体感/湿度/风/三日预报 → 天气 title；归属运营商/v6 对端 → IP title。原则沉淀：附加区「内容行 ≤1 + 状态行 ≤1」，超出即收进 hover。
> **v0.3.3 位置修订（四轮反馈「天气黄历把搜索框挤开了」）**：小组件不再进时钟区——天气/黄历/IP **统一沉页脚信息组**（自上而下：天气 → 黄历主/辅行 → IP → 品牌行），核心区（时钟/搜索/最常访问）位置恒定（实测搜索框 y 坐标开/关组件完全一致 287px）。
> **v0.3.2 走查修订（同三轮反馈「IPv6 还在、点击切不回 IPv4」）**：v0.3.1 只解决了新缓存的默认择优，**但旧粘滞缓存不重探、且「点击=重探碰运气」的语义根本不对**。改为：① 探测**全部候选入缓存**（`{candidates: IpInfo[]}`，兼容旧格式读取，v4/v6 同时在场）；② **点击 = IPv4/IPv6 即时切换**（hover title 提示对端地址；单族时才退化为强刷重探）；③ 展示族偏好持久记忆（storage `widgetPrefs.ip`，默认 IPv4，不占设置面）；④ 择优逻辑下沉 shared（`pickIp`/`bestIp`，含去重与归属优先）+ 单测。真机复现旧粘滞现场验证：种纯 v6 缓存→点击→回 v4+归属→双向切换 <0.4s→重开记忆保持。⚠️ 交付注意：**wxt/esbuild 构建不校验运行时 import**——本轮曾因漏 import `getWeather` 整页白屏，任何扩展端改动必须跑真机 smoke，不能只看构建成功。

## 1. 设计原则

1. **注册制组件**：与 `lib/modules.ts` 能力模块同构——新标签页维护 `WIDGET_REGISTRY`，每件 = 描述符（id/名称/图标/取数 TTL）+ 内联渲染器 + 取数函数。新增组件零侵入：注册即用，设置页开关自动出现。
2. **不破坏 D40 极简心智 + 无盒子内联（v0.3）**：页面骨架仍是「品牌标 + 时钟 + 搜索 + 最常访问」；组件**没有自己的区域**，内容按语义散入既有字层（时钟区/页脚），字号颜色沿用所在位置现值；出厂默认全关（Q1），关掉时页面与 D40 逐像素一致。
3. **零新增 host_permissions**：所有第三方端点均实测返回 `access-control-allow-origin: *`，扩展页 fetch 走标准 CORS，无需权限——不增加商店审核摩擦，用户可见权限面不变。
4. **隐私口径**：组件出站请求只携带最小信息（天气城市名 / IP 探测本身），**永不携带书签数据、URL、标识符**；开关行可注明数据源。与「隐私域名校验在抓取/AI 前执行」红线正交（那管书签内容，这里无内容出境）。
5. **优雅降级**：多源回退 + 本地缓存；断网显示上次数据并尾注「未更新」（对齐 D18 本地缓存只读哲学）；首次取数失败显式内联小字 + 重试（D40 教训：不静默吞错）。

## 2. 数据源实测结论

### 2.1 公网 IP（浏览器直连，不代理——代理拿到的是 NAS 的 IP，语义错误）

| 端点 | 国内直连 | CORS | 返回 | 结论 |
|---|---|---|---|---|
| `myip.ipip.net` | ✓ | `*` | 中文文本「当前 IP：x.x.x.x 来自于：中国 湖南 怀化 电信」 | **主源**（一请求得 IP+归属+运营商，也是天气定位数据源） |
| `api.ip.sb/ip` | ✓ | `*` | 仅 IPv4 | 回退源（`/geoip` 403 需 key，弃用） |
| `cloudflare.com/cdn-cgi/trace` | ✓ | `*` | `ip=` 行（可能 IPv6）+ loc/colo | 回退源 |
| `api.ipify.org?format=json` | ✗ 无响应 | — | 仅 IP | 海外兜底源 |
| `ipapi.co` / `bigdatacloud` | 403 | — | — | 归属地兜底源全部不通，城市只能靠 ipip |

**策略（v0.3.2）**：全源**并行探测，候选全量入缓存**（v4/v6 都保留，兼容读旧格式）；fast path「IPv4+归属」到手即再等 2s 收另一族；展示默认 IPv4+归属（`bestIp`），**点击在 IPv4/IPv6 间即时切换**（`pickIp` + `widgetPrefs.ip` 记忆）；缓存 24h。⚠️ 勿改回顺序探测（首成功即停→单族粘滞），也勿把点击退化成「只能重探」（用户心智：点击=切换格式）。

### 2.2 天气（最大坑：Open-Meteo 预报端点国内直连不通）

| 端点 | 国内直连 | CORS | 结论 |
|---|---|---|---|
| `wttr.in/<城市>?format=j1` | ✓ 1.5s | `*` | **主源**：免 key，中文城市名可用，current+3 日预报+WWO 天气码（`lang_zh` 实际仍返回英文，不依赖，自建码表） |
| `geocoding-api.open-meteo.com` | ✓（Cloudflare CDN） | `*` | 备源链路的城市→经纬度 |
| `api.open-meteo.com/v1/forecast` | ✗ 20s 超时（OVH 单 IP） | `*` | 结构最好但**国内直连不通**——仅海外/有代理环境生效 |
| 和风天气 / 高德 | — | 需 key | BYOK 槽位降级 W3（v0.2 口径下连城市都不配置） |

**策略**：城市取自 IP 归属地（无任何用户输入与配置存储）→ wttr.in 主查 → Open-Meteo 备查；归一化统一 `WeatherSnapshot` + WWO/WMO 双码表映射中文文案（`packages/shared`）。缓存 30 分钟。**已知取舍**：走代理/VPN 时城市随出口漂移——「零配置」口径下接受。
**二期可选（W3）**：自建端「经服务端代理」开关（NAS 统一出站+全设备共享缓存；天气无隐私敏感性，复用 fetch-guard 白名单），解决纯外网不通环境。

### 2.3 黄历（纯本地计算，零网络零隐私成本）

- **`lunar-typescript`**（6tail，MIT，无第三方依赖）：实测 ESM 入口 raw 448KB / **gzip 111KB**，仅进扩展 newtab 分包（服务端经子路径出口隔离，不碰 NAS 内存/镜像红线）。
- 实测输出：农历、干支纪年纪日、生肖、宜/忌、节气、节日、冲煞、彭祖百忌——超出任何黄历 API 能力，且**离线可用**。
- 渲染（v0.3.1 两档字阶）：主行 `农历十月十二 · 丙午马年`（text-sm neutral-500，页面第二视觉焦点；有节气/节日时替换干支年显示它）；辅行 `宜 合帐 裁衣   忌 置产 造船`（11px neutral-400，各取 2 项，左右分栏间距拉开）。跨零点自动换日：30s 定时器对比 date 边界，仅跨日才重算。

## 3. 组件架构（v0.3 内联形态）

```
apps/extension/src/widgets/
  registry.ts   # WIDGET_REGISTRY = [ip, weather, almanac]（label/icon，无 settings——v0.2 只有显隐）
  fetchers.ts   # 通用 TTL 缓存（chrome.storage.local['widgetCache']）+ IP 多源回退链 + 天气自动定位链
  inline.tsx    # WeatherInline / AlmanacInline / IpInline——无盒子渲染器 + useWidgetData hook（挂载/回前台按 TTL 校验）
```

纯逻辑（ipip/trace 文本解析、天气码映射、黄历格式化）下沉 `packages/shared`：`src/widgets.ts`（零依赖，经 index 出口）+ `src/almanac.ts`（依赖 lunar-typescript，**仅经 `@mf/shared/almanac` 子路径出口**，不进服务端 bundle）。

**数据模型**（`ntpConfig` 向后兼容扩展，现有键不动）：

```ts
interface NtpConfig {
  topCount: number
  engines: string[]
  widgets: string[] // 启用 id 列表，缺省 []（全关）；顺序恒按 registry，无需持久化顺序
}
```

**内联布局（v0.3.3：组件没有自己的区域，统一沉页脚信息组）**：
- 页脚自上而下：`怀化 ☀️ 16°`（text-xs，体感/湿度/风/三日预报收进 hover）→ 黄历主/辅两档字阶（见 §2.3）→ `223.149.24.85 · 湖南 怀化 · 电信`（text-[11px]，双栈点击=**IPv4/IPv6 即时切换**带记忆，单族点击=强刷）→ `⚡ 由 my-favorites 生成`。
- **核心区（时钟/搜索/最常访问）不随组件开关位移**——天气/黄历不占时钟区（v0.3.3 用户反馈：挤开搜索框），各组件独立成行、开关互不影响布局。
- 字号/颜色沿用所在字层现值；不加盒子、阴影、边框；窄栏 `max-w-2xl` 不变。
- 失败态：内联小字（「天气不可用」）+ 下划线重试；stale：尾注「·未更新」。

**设置交互（只有显示/隐藏）**：自定义面板内一行 chips `🌐 公网 IP / ⛅ 天气 / 📅 黄历`，点了就开/关，无任何 per-widget 设置项；即时生效（存 storage + 重渲染），与 engines chips 一致。

**刷新节奏**：打开新标签页即取（TTL 内命中缓存不出网，先渲染缓存）；weather 30min / ip 24h / almanac 无网络；`visibilitychange` 回前台超 TTL 才重取；无常驻取数定时器（黄历的跨日检测除外，30s 空转零成本）。

## 6. 决策记录（2026-11-20 用户拍板）

- **Q1 出厂默认**：三件全关，保 D40「安静」承诺，用户主动开启。
- **Q2 IP 归属地**：**不做开关**——用户可控制的只有显示/隐藏；内容固定（IP + 归属/运营商，随 ipip 主源天然可得）。
- **Q3 天气**：浏览器直连 wttr.in 为主，Open-Meteo 预报仅作海外备源；服务端代理降级为 W3 可选。
- **Q4 和风/高德 BYOK**：W3 再议。
- **Q5 排序**：不做（属显隐之外的控制）；顺序恒按 registry。
- **v0.3 视觉**（追加）：不做卡片——组件内容内联进页面既有字层，与页面融为一体（用户反馈定样）。

## 7. 验收标准

1. 全关状态下新标签页与 D40 现状逐像素一致；✅
2. 三组件开启后真机首屏 ≤300ms 出缓存内容，断网显「未更新」不白屏；✅（真机实数据验证）
3. 黄历离线正确（农历/干支/宜忌与库口径快照断言，走查时可再抽测）；✅
4. 零新增扩展权限、零书签数据出境；✅
5. 单测 73 + E2E 4 全绿；文档回写（功能文档 v0.3.7 · D41）；✅

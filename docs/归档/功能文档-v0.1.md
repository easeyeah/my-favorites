---

## 1. 产品定位

一句话：**把浏览器收藏夹变成一个基于 AI 整理、内容可感知、持续自动维护的个人导航站点。**

核心差异点（相对现有书签类产品）：

1. **内容感知整理**：不只看书签的标题/URL，而是抓取并缓存网页正文，基于"页面实际内容"做分类与整理，结果更贴合真实用途。
2. **聊天式整理**：通过对话指定"把哪些书签、怎么整理"，AI 执行并给出可预览、可回滚的结果。
3. **产出是导航站点**：整理结果直接落地为一个可用的网址导航主页（多种内置模板一键套用），而不只是书签列表。
4. **云端托管维护**：查重、死链检测等周期性任务在云端定时执行，用户无感。
5. **可自建服务端**：面向 NAS 用户，提供 Docker 一键部署的私有服务端，数据完全自持。

## 2. 竞品参考分析

### 2.1 笔点 — 书签秒变个人主页（1263 用户，免费）
- 一键收藏，不限数量分类目录，多浏览器云端同步
- 一键保存文章正文，稍后阅读
- 书签一键生成个人主页，公开链接分享给好友
- 强搜索：名称 / URL / 备注，支持搜本地书签和历史记录
- 保存/恢复全部标签页，跨设备同步
- 历史记录查看、搜索、云端自动备份
- 右键收藏网页文本、图片到云端

**可借鉴**：一键收藏、个人主页分享、"书签 → 主页"的产出形态、稍后读。
**其短板（即我们的机会）**：纯手工分类、无 AI、无内容理解、无死链维护。

### 2.2 HamHome — AI 书签管理与网页收藏（108 用户，BYOK）
- AI 基于页面内容自动分类、推荐标签、生成摘要
- AI 语义搜索 + 对话式查询；BYOK（OpenAI / Anthropic / Ollama / 自定义端点）
- 预设分类模板（通用型 / 专业创作者型）一键导入；AI 根据使用场景生成定制分类；无限层级树形分类
- 本地完整 HTML 网页快照，原页失效仍可读（基于 Mozilla Readability 提取正文）
- 全文搜索（标题/描述/内容），按分类、标签、时间筛选，可保存筛选预设
- 隐私优先：数据全本地（Storage + IndexedDB），隐私域名排除不分析，JSON 导入导出
- 瀑布流/列表视图、深浅色主题、中英 i18n、快捷键

**可借鉴**：BYOK 模式、预设分类模板、Readability 正文提取、隐私域名排除、快照防失效。
**其短板**：数据仅本地无多端同步、无导航站产出、无定期维护任务、无服务端形态。

### 2.3 书签同步管理 BookmarkSync（beta）
- 多设备书签自动同步，不依赖 Google 账号
- 云书签：低频书签归档到云端，不占书签栏
- 私密书签：二次密码验证的加密存储空间
- 数据加密传输与存储，多语言

**可借鉴**：私密书签（二次验证）、常用/备用分层管理、不依赖厂商账号的同步（呼应自建服务端）。
**其短板**：无 AI、无内容处理。

| 用户 | 场景 |
|---|---|
| 普通重度收藏用户 | 收藏夹几百条历史堆积分不清，想一句话让 AI 清理归档 |

## 4. 功能架构总览

```
┌──────────────────────────────────────────────────┐
│                 浏览器扩展（前端入口）              │
│  一键收藏 / 书签导入 / 聊天整理面板 / 导航页入口     │
└───────────────┬──────────────────────────────────┘
                │ API（HTTPS / WebSocket）
┌───────────────▼──────────────────────────────────┐
│                服务端（两种形态，同构 API）          │
│  A. 官方云端（SaaS，开箱即用）                      │
│  B. 自建服务端（Docker 镜像，NAS 部署，数据本地化）  │
│                                                  │
│  核心服务：                                        │
│  · 书签与目录服务      · 内容抓取与缓存引擎          │
│  · AI 整理编排（LLM）  · 导航站生成与托管            │
│  · 定时维护调度（查重/死链）  · 同步与账号/加密        │
└──────────────────────────────────────────────────┘
```

两种服务端形态共享同一套核心服务，扩展端只需切换服务地址，这是自建方案可行的关键。

## 5. 功能模块详述

### F1 书签获取与管理
- **F1.1 本地书签导入**：一键读取浏览器全部书签（含文件夹结构、添加时间），解析 HTML 书签文件导入（Netscape 格式，兼容各浏览器导出）
- **F1.2 一键收藏**：扩展快捷键/右键收藏当前页，可指定目标分类；支持稍后读
- **F1.3 树形目录管理**：无限层级分类；支持"常用 / 备用"分层（参考 BookmarkSync 云书签思路：低频书签归档不占书签栏）
- **F1.4 私密书签**：二次密码验证的加密分区（参考 BookmarkSync）
- **F1.5 多端同步**：书签数据跨浏览器、跨设备同步（官方账号 或 自建服务端）
- **F1.6 导入导出**：JSON 全量备份 / Netscape HTML 导出，保证数据可迁移（可随时离开）

### F2 内容抓取与缓存引擎（内容感知的基础）
- **F2.1 网页正文抓取**：服务端抓取书签 URL 页面，Readability 算法提取正文、标题、描述、关键图片
- **F2.2 多级缓存**：
  - L1 结构化摘要（正文提取 + AI 生成摘要 + 标签/关键词）
  - L2 正文文本（用于语义检索与整理上下文）
  - L3 页面快照（完整 HTML 或净化 HTML，原页失效/改版后仍可回看）
- **F2.3 站点图标/封面**：favicon、og:image 抓取与本地缓存（导航站展示必需）
- **F2.4 抓取策略**：
  - 队列化、限速、重试；失败标记（超时/反爬/登录墙）进入降级通道
  - 登录墙/内网页面标注"仅元数据"，不强行抓取
  - **隐私域名排除清单**（参考 HamHome）：名单内域名只存 URL 不抓内容
- **F2.5 内容向量索引**：正文与摘要生成 embedding，支撑语义搜索与聚类

### F3 AI 聊天式整理（核心交互）
- **F3.1 对话入口**：扩展侧栏 / 导航站内嵌聊天框
- **F3.2 指定范围整理**：支持自然语言圈定操作对象，例如：
  - "把 '开发' 文件夹里 2023 年以前的链接按内容重新分类"
  - "整理所有带 'github' 的书签"
  - "把收藏里的教程类内容单独建一个 '学习' 目录"
- **F3.3 AI 整理动作**（聊天可触发的原子操作）：
  - 自动分类（基于缓存正文+摘要，而非仅标题）
  - 生成/改写书签名称与描述、推荐标签
  - 合并重复项、识别失效项并给处置建议
  - 建立新目录结构（可参考内置分类模板，或描述场景让 AI 生成定制结构）
  - 批量归档低频书签到"备用区"
- **F3.4 结果预览与确认**：整理以 **diff 预览 → 用户确认 → 应用** 的方式执行，不做静默改动
- **F3.5 可回滚**：每次整理生成一个"整理快照"（版本），一键撤销
- **F3.6 BYOK**：支持自带 API Key（OpenAI / Anthropic / Ollama / 自定义端点）；自建服务端可完全用自己的模型
- **F3.7 整理报告**：一次整理结束后输出摘要报告（移动 N 条、合并 N 条、疑似死链 M 条）

### F4 导航站点生成
- **F4.1 一键生成**：把（选定范围的）书签渲染为导航站点，获得一个访问地址
- **F4.2 内置导航模板**（首批 4–6 套）：
  - 经典宫格式（类 hao123，搜索框 + 分组卡片）
  - 极简清单式（文字为主，快速跳转）
  - 卡片瀑布流式（图标+封面+摘要，偏内容感）
  - 个人主页式（头像/问候语/常用推荐/天气位，类起始页）
  - （预留）极客自定义式：模板 DSL + 自定义 CSS
- **F4.3 模板能力**：分组折叠、搜索框（本地书签搜索+可选外部搜索引擎）、深浅色主题、响应式、自定义背景/Logo/标题
- **F4.4 发布控制**：私有（登录可见）/ 公开（随机链接）/ 密码访问
- **F4.5 内容联动**：导航卡片展示 AI 摘要/图标/封面（来自 F2 缓存）；死链书签自动打标或隐藏（联动 F5）
- **F4.6 设为起始页**：扩展支持把导航站设为新标签页

### F5 定期自动维护（云端/服务端托管）
- **F5.1 死链检测**：
  - 周期性（默认每周，可配）批量探测全部/增量书签
  - 判定策略：HTTP 状态 + 重定向跟踪 + 超时/重试；区分"确认失效 / 疑似失效(反爬) / 正常"
  - 结果通知（扩展角标 / 站内 / 可选邮件），并提供处置动作：跳转、归档、删除、**AI 搜索替代站点建议**（可作为亮点）
- **F5.2 内容变更检测**（进阶）：正文变化时更新摘要与快照
- **F5.3 查重**：URL 规范化（去 tracking 参数、统一协议/末斜杠）+ 相似检测（同域同名、同 URL 不同参数），输出合并建议，确认后执行
- **F5.4 调度**：官方云端统一调度；自建服务端内置 cron 调度器，任务在本地执行
- **F5.5 维护报告**：每次任务生成报告并留存历史

### F6 部署形态与服务端
- **F6.1 官方云端（SaaS）**：注册即用，免费额度 + 订阅制（存储空间、快照数量、AI 用量）
- **F6.2 自建服务端（Docker）**：
  - 单镜像一键部署（`docker run` / docker-compose），NAS 友好（群晖/Unraid/威联通）
  - 与云端**同一套 API**，扩展端只需改服务地址；内置 Web 管理台
  - 支持配置自己的 LLM（Ollama 本地模型 / 任意 OpenAI 兼容端点），实现全离线运行
  - HTTPS/反代文档、自动备份（定时导出到指定目录）、数据迁移工具（云端 ↔ 自建）
- **F6.3 降级形态——纯本地模式**：不部署任何服务端时，扩展本地 IndexedDB 提供基础功能（收藏/分类/快照/搜索），AI 走 BYOK 直连；导航站可本地渲染导出为静态 HTML 文件

### F7 搜索与浏览
- **F7.1 全文搜索**：标题 / URL / 备注 / 缓存正文
- **F7.2 语义搜索**：基于向量的"按意思找"
- **F7.3 筛选**：分类 / 标签 / 时间 / 状态（正常/死链/待整理）/ 访问频率；可保存筛选预设
- **F7.4 视图**：网格 / 列表；深浅色主题；中英文界面

### F8 隐私与安全
- 隐私域名排除清单（不抓取、不分析）
- 私密书签二次验证 + 加密存储（自建端密钥由用户掌握）
- 数据所有权承诺：随时完整导出/删除
- 敏感操作（批量删除、发布公开导航站）需确认

## 6. 非功能需求（摘要）

- 性能：导航站首屏 < 1.5s；千级书签整理 diff 渲染流畅
- 抓取礼貌性：限速、robots 尊重、单站并发 ≤ 2
- 可用性：AI 整理失败可手动兜底；服务端不可用时扩展降级为本地模式
- 兼容：Chrome / Edge（Manifest V3），Firefox 列入后续
- 安全：全部传输 TLS；服务端提供首次安装强制设置管理员密码

## 8. 开放问题（请评审时给结论）

1. **产品形态优先级**：先做浏览器扩展 + 服务端，还是先做独立 Web 应用（手动导入书签文件起步）？影响 M1 工作量与上架周期。
2. **导航站的公开分享**是否要支持"被收录/被搜索"（公开导航广场）？这会显著增加审核与合规成本，建议 M1 先做纯私有/链接分享。
3. **AI 用量商业模式**：SaaS 订阅（我们出 token 成本）+ BYOK 免费，还是统一 BYOK 优先？建议后者起步以控制成本。
4. **快照存储边界**：L3 完整 HTML 快照体积大，云端版是否限制快照数量/只存净化版正文？自建端可不限。
5. **死链误判处理**：反爬/登录墙站点容易被误判，是否接受"疑似失效仅标注不自动处置"的保守策略？（建议接受）
6. **命名**：项目代号 my-favorites 是否作为最终产品名？
7. **目标浏览器**：你三个参考都是 Edge 商店，首发 Edge + Chrome 双上架，还是只先 Edge？

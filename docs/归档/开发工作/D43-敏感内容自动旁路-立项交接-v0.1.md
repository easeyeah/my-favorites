## 一、决策口径（D43 草案）

三条风险面与对策：

1. **AI 外发面（核心）**
   - `packages/shared` 新增**敏感宿主启发式判定**：`sensitive.ts` = 纯数据关键词表（host 子串匹配，如 porn/xxx/jav/hentai 类 token，**不内置真实站点全名**）+ `isSensitiveHost(url)`（解析失败返回 false——不可解析已被隐私门按保守处理覆盖）。
   - 整理功能点 `POST /tidy/sensitive`（tidy 模块）：全库扫描未标私密的命中项 → `is_private=1` + 移入私密目录（find-or-create「私人收藏」）+ 镜像入队 + **写 organize_version（可撤销）**；单事务。
   - organize LLM **批次隔离降级**：provider 审核类错误 → 批次二分重试定位肇因项 → 该项标私密跳过，其余正常分类，整次整理不再因个别条目失败。
2. **本地可见性面（必须配套，否则功能上线即"数据消失"恐慌）**：web 管理台目前从不发 `X-MF-Private: 1`，标私密后条目在控制台完全不可见。需加「显示私密」开关（api 层带请求头）+ 私密项可逐条取消标记。
3. **公开投影面**：红线④ + `is_private` 投影过滤已实现，无需新设计。

配置面 = 0 个新开关（符合最小配置面原则）；自动化结果如实进版本历史。

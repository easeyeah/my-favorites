# 架构与功能评估（v0.1）

> 日期：2026-11-18；评估基线：`fd8e8b033d4168cb3633649646b69a3c016b3d05`。
> 方法：阅读现行产品/技术文档、上一轮任务与总结，静态检查服务端、扩展、Web、共享包、CI 和部署文件。
> 范围：只新增开发文档，未修改产品代码，未运行本轮运行时验证。以下“确认”指可由代码直接确认的事实，不表示已复现生产事故。
> 权威边界：本文件是执行建议，不替代现行功能文档或追加既定决策；落地变更时按项目规范回写并递增权威文档小版本。

## 1. 总体判断

**技术方向适合单用户自建产品，暂不需要更换技术栈；当前最需要补齐的不是功能数量，而是安全边界、可恢复状态机和真实交付闭环。**

建议把现阶段定位为“有较完整功能原型和一轮可靠性基础的自建预览版工程”，而非“M1–M3 全量产品已交付”。

已有值得保留的基础：

- pnpm/Turbo + TS 全栈，扩展/WXT、Web/React、API/Hono 的职责方向合理。
- 单容器、SQLite WAL、server bundle、无 Redis，符合 NAS 约束。
- 已有版本化迁移、迁移前一致性备份、Provider Key 加密入口。
- 已有共享隐私策略、设备身份映射、浏览器待执行记录。
- 聊天提案 apply 已有事务、修订号冲突检测；合并已改为软归档。
- 具有可继续扩展的单元/API/E2E 样本与历史回归记录，不必推倒重来。

不足主要集中在：

1. 同类动作存在多入口，策略只在部分入口执行；公开导航、搜索和快照旧接口尤其需要收口。
2. “有持久表”尚不等于“有可靠队列”；重试、认领、恢复、冲突和补偿未形成闭环。
3. “有事务 apply”尚不等于“所有自动移动可恢复”；收件箱、镜像和撤销仍有分叉实现。
4. 核心价值的实现深度不足：内容分类仍被域名锁死，diff 不能逐项采纳，搜索缺少匹配解释，离线入口不存在。
5. JSON 导出/迁移备份不等于完整备份；干净部署、真实快照与资源红线尚缺足够门禁。

## 2. 当前真实部署能力

| 能力 | 当前判断 | 后续处理 |
|---|---|---|
| 扩展 + 单用户 Docker | 当前最完整路径，但存在本报告阻断项 | 本轮唯一交付主线 |
| 纯本地运行 | 新标签页仍依赖服务端；未见完整 IndexedDB/OPFS 后端实现 | 后续独立立项，不以导航缓存替代 |
| 官方云 SaaS | `MF_FORM` 分支不等于租户模型；当前库主要为单用户 SQLite | 禁止按“切 env 即可上线”宣传 |
| 浏览器同步 | 存在收件箱镜像和另一套 `syncMirror`；不是完整双向同步 | 收敛到 D16/D20 的可选镜像 |
| 私密书签 | 标记/显示控制，非二次验证 + 客户端加密 | 继续实验性；优先杜绝公开泄露 |
| 全离线 AI | Ollama 路径可配置，模型预拉取及资源边界需验收 | 分别计量 server 与模型服务 |
| 备份 | 迁移前 DB 备份已有；JSON 不覆盖完整恢复 | 分开命名并补完整备份 |

现行 D14–D20 已明确单用户自建优先，不应以早期路线图反向要求本轮交付支付、模板 DSL、多租户或完整纯本地。

### 3.1 优先级解释

- **P0**：隐私、安全、数据一致性阻断；不能以“先标实验性”保留默认危险路径。
- **P1**：核心可用性与可靠性；其中权限、导入不丢、原始 URL、完整恢复同样是发布门禁，不因编号低于 P0 而允许跳过。
- **P2**：低风险体验增强或基础交付整理。优先级不是工期估算。
- 对可能的数据泄露，仅确认可达代码路径；范围、历史是否发生、具体浏览器行为须由隔离测试确认，不能据此声称已有事故。

## 4. 目标架构：收口而不是重写

```text
扩展 popup / sidepanel / newtab / options
    └─ 统一 API 客户端（上下文、权限、错误、超时）
       + 端侧持久 outbox（实例隔离、串行写、alarms 唤醒）
       + 端侧隐私判定（读取前、上传前）
       + 导航缓存（非完整本地模式）
                  ↓
Hono 路由：认证/请求 schema/授权/错误映射
                  ↓
应用服务：Bookmark / Organize / Content / Publication / Backup
    ├─ Policy：共享隐私动作 + 对象可见性 + 出站网络策略
    ├─ Unit of Work：实体修改 + revision + 版本历史 + change + outbox
    ├─ JobQueue：SQLite 持久任务、租约、重试、取消、去重
    └─ Repository / BlobStore：SQL 与文件生命周期集中管理
                  ↓
单个 SQLite + /data 文件；同容器有界 Worker
```

### 4.1 建议模块边界

保留现有应用结构，逐域提取；目录名为建议，可随首个 PR 调整：

- `packages/shared/src/contracts/`：请求/响应 zod schema、错误码、版本兼容、分页结构；不要共享整张数据库 Row 给前端。
- `apps/server/src/routes/`：按书签、整理、内容、分享、设置拆 Hono 子路由。
- `apps/server/src/services/`：跨表事务、权限调用、业务状态机；禁止控制器直接拼 SQL。
- `apps/server/src/repositories/`：从 Store 渐进拆分，不一次性换 ORM。
- `apps/server/src/jobs/`：SQLite JobQueue + 调度器；同一接口，当前只实现自建适配，不预写云端空壳。
- `apps/server/src/storage/`：本地 BlobStore，临时文件、提交、清理、备份清单统一管理。
- `apps/extension/src/lib/`：上下文/API、隐私、outbox、镜像、导航缓存分模块。
- `packages/ui`：仅提取已被两端实际使用的 diff/状态组件；不要为“复用”把所有 UI 一次迁走。

### 4.2 三个关键事务边界

1. **整理/收件箱**：异步计算候选在事务外；提交时在短事务内重读权限/revision/目录，原子写实体、版本、变更日志、镜像 outbox。事务内不 await 网络。
2. **浏览器执行**：无法与 DB 共用事务，采用至少一次投递 + 操作 ID 幂等 + 前置状态检查 + 回执；不承诺 exactly-once。撤销是一条可审计的新业务操作，并生成反向 outbox。
3. **快照/完整备份**：文件系统与 DB 非同一事务；使用暂存、校验、原子改名、索引状态和补偿清理。备份必须同时冻结/保护快照文件集合，单独 VACUUM INTO 不能保证 DB 与文件一致。

### 4.3 必须统一的数据规则

- 身份：`server_instance_id + principal_id + device_id`；浏览器节点另用稳定映射；名称/URL 只用于匹配候选，不作操作身份。
- 内容版本与用户操作版本应分开；维护状态更新不应自动视作用户否决整理，语义由 DEV-08 定义。
- 用户可见范围：私有库、实验性私密、软归档、公开发布清单分别定义，公开接口必须显式传 publication scope，不能复用“全库 search”。
- URL 原文与去重键分离；旧去重键迁移只能从仍存在的 raw 重算，已被历史导入跳过的记录无法凭空恢复，提供重新导入指引。
- 内容和向量保存来源、时间、模型/提取器版本、内容 hash、规则修订；旧结果不覆盖新修订。
- 任何长任务均有真实 scope/total/processed/skipped/failed，不能以 LIMIT 子集冒充全库处理。

## 5. 功能完善方向

| 用户任务 | 需要补齐 | 不应优先扩张 |
|---|---|---|
| 放得进 | NAS 权限授权、收藏/捕获分状态、持久续传、重复解释、原 URL 保真 | 更多收藏渠道 |
| 找得到 | 中文关键词/正文命中、片段解释、筛选、资料库分页、原页/快照入口 | 先做问答式知识库 |
| 不乱动 | 逐项 diff、稳定目录 ID、真实冲突提示、撤销历史、人工优先 | 更激进自动归类 |
| 不泄露 | 全入口统一策略、失效规则保守拒绝、分享范围明确 | 更多分享模板 |
| 带得走 | 完整备份、空实例恢复、校验与演练 | 复杂增量迁移合并 |
| 用得久 | 离线导航、少量常用固定项、维护报告可处理、错误可诊断 | 高频打扰通知 |

中英 i18n、键盘操作与无障碍应随核心页面重构逐步纳入，不另起大规模视觉改版。

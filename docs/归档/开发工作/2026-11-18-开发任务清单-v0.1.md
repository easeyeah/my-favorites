## 2. P0：安全与一致性阻断

### DEV-01：公开分享范围与密码保护

**目标/证据**：E01/E02。阻止公开搜索绕开站点密码、未选择内容被整库发布，以及 PATCH 清空密码。

**范围**：`server/src/app.ts` 的 `/s/*`、发布路由，`nav.ts`、Store 的 nav 方法；Web 分享页、新标签搜索入口。

**实施步骤**：

1. 用隔离数据建立：公开项、未发布项、私密项、软归档项；分别请求公开站和 `/s/search`，记录修复前行为。
2. 立即关闭匿名全库搜索。私有搜索走已鉴权 API；公开搜索必须携带站点标识并限制到该站的显式发布集合。
3. 发布配置增加书签/目录选择、visibility、revision、撤销发布；默认私有，展示“将公开 N 项”的确认页。仅发布元数据/允许的摘要，不包含正文、快照内容、内部路径和凭据。
4. 旧站点缺少显式发布集合时先设为待确认/不可公开，不默默继续全库公开；已有分享链接迁移变化写入升级说明。
5. PATCH 以完整当前配置为基线；缺字段保持原值，显式 null 才移除密码；读取接口不回传 password_hash。
6. 密码不再放查询参数。使用 POST 验证 + 短期、限定站点/revision 的访问凭证（如 Secure/HttpOnly/SameSite Cookie），增加限速、无敏感缓存与无 referrer 泄漏；撤销/改密使旧凭证失效。
7. slug 改用加密随机源并处理唯一冲突；删除重复注册的 `/s/:slug`，确保唯一实现路径。

**验收**：匿名/错误密码无法搜出受密码站点内容；站点 A 授权不能访问 B；未发布、私密、软归档项目不出现在 HTML/JSON/搜索/计数；只改 title 保留 password/template；撤销/改密后旧凭证无效；快照正文不进入任何公开响应。

**交付**：授权矩阵、升级迁移、API/浏览器用例、分享确认截图。**不做**：公开广场、模板新增、举报后台。

### DEV-02：统一对象可见性与旧接口封堵

**目标/证据**：E03。所有读入口对私密、软归档、快照执行相同边界。

**范围**：search/content/snapshot/export/nav 路由、`store.ts`、`semantic.ts`。

**实施步骤**：

1. 先列出读入口，定义 `AccessContext`/`VisibilityScope`：管理员私有库、实验性私密显示、公开站集合；不把客户端 `X-MF-Private` 当成二次验证证明。
2. 仓储查询显式接收 scope，默认排除软归档和未授权私密；过滤在分页前进行，total 与返回条目一致。
3. `/content/:bookmarkId` 从书签对象授权后再读取；快照旧 `/snapshots/:id` 删除/返回迁移错误，或内部统一跳到受控下载实现，不再存在第二套无策略的直读。
4. 私密标记开启时清理/冻结派生内容的规则，与 DEV-03 统一；对“只隐藏未加密”的实验性 UI 明示。
5. 关键词/语义/HTML/JSON/导航/统计逐入口补越权测试；书签不存在与不允许读取的错误避免泄露多余元数据。

**验收**：相同对象在所有默认读入口均不可见；只知道 bookmark/snapshot ID 不能绕过；旧接口不能拿到未净化内联内容；语义搜索不返回合并来源项；分页没有过滤后空页/错误 total。

**交付**：可见性策略与参数化回归测试。**不做**：实现加密保险箱。

### DEV-03：隐私失效策略与异步写回安全

**目标/证据**：E04/E05。恢复“设备端先阻止读取，服务端再防守”的真实保证。

**范围**：共享隐私引擎、扩展 privacy/config、organize/pipeline/semantic/维护入口、存量清理。

**实施步骤**：

1. 规则缓存明确 `unknown/fresh/stale/error`；内置规则与用户规则分层。缺失或 stale 时敏感五动作拒绝，保留标题/URL 基础收藏；保留旧用户规则用于拒绝，不因过期丢弃后放行。
2. 按实例/主体隔离规则，切换上下文时暂停敏感任务直至规则刷新；规则更新通知到 SW，各次读取与上传重新检查。
3. 所有模型入口（摘要、整理、收件箱、embedding，包括只发标题/URL）统一走 `call_model`；禁止调用者漏传私密状态。`embedBookmark` 不能绕过被 capture 拒绝的判定。
4. LLM/抓取任务记录内容 hash、实体修订、规则修订、上下文；响应完成后在提交前重新读取策略与状态，过期结果丢弃且给原因码。
5. 规则变更清理要包含软归档来源、派生向量、封面/摘要字段及快照；扫描分页不静默截断。文件删除失败不能“删索引即成功”，保留待清理记录；此为用户发起隐私规则变化的派生内容清理，不授权自动删除原书签。
6. 日志/诊断仅保留原因码，不记录模型输入、URL 查询参数、凭据和响应正文。

**验收**：给陌生自定义隐私域，缓存过期/网络断开/损坏/切换服务器后，DOM 读取和上传函数调用次数均为 0；直接调用 embedding/整理/维护不外发该域；模型等待期间加规则或设私密，返回后无派生数据写回；已软归档内容也被清理。

**交付**：五动作调用矩阵、扩展 spy/网络断言、异步竞态回归。**不做**：承诺追回第三方已接收内容。

### DEV-04：出站网络统一防护与资源边界

**目标/证据**：E06。抓取、死链检查均不能绕过网络和隐私策略，慢响应不能耗尽 NAS。

**范围**：`fetch-guard.ts`、maintenance/crawl、响应体读取；Provider 使用独立“管理员配置模型端点”策略，不直接套禁私网规则阻断 Ollama。

**实施步骤**：

1. 维护 HEAD/GET 也先做五动作策略，再走统一请求器；每跳重新授权和校验，限制 hop、端口/协议；跨主机重定向禁止继承敏感头。
2. 使用经过审查的 IP/CIDR 解析，正确处理 IPv6 压缩、mapped IPv4、链路本地全范围、保留地址；禁止使用字符串 split 近似 CIDR。
3. 消除 DNS 校验/连接二次解析窗口：在 Node 连接层固定已验证地址，保留正确 Host/TLS SNI，并处理多地址/fallback；选择轻量可 bundle 的实现，写 ADR 说明资源影响。
4. 超时覆盖 DNS、连接、响应头和响应体总时长；流式字节上限先于整包分配，超额/取消及时 cancel body；HEAD/GET 不需要内容时释放连接。
5. 区分内容抓取网络策略与管理员模型端点：Ollama 仅向明确配置的地址发请求；连接测试和实际调用策略一致，禁止凭重定向把 Key 送往其他端点。

**验收**：用本地可控 DNS/重定向测试替身验证禁止网段实际连接数为 0；混合 DNS、IPv6、rebind、慢 header/body、chunked 超限、重定向循环均被阻断；允许清单/Ollama 正常；不访问真实云元数据服务来做测试。

**交付**：网络威胁模型、请求器、故障测试、峰值内存记录。**不做**：绕过站点反爬。

### DEV-05：认证、首启与令牌生命周期

**目标/证据**：E07/E08。环境变量密码和 DB 密码同等防护，提供用户能真正操作的撤销。

**实施步骤**：

1. 统一两种登录模式的速率限制/密码比较/错误码，限制表有容量和过期清理；可信代理白名单之外不采信 X-Forwarded-For。
2. 来源白名单支持管理台同源、配置的扩展来源与开发白名单；未认可 Origin 拒绝。CORS 不代替认证，非浏览器请求仍按认证处理。
3. setup 增加部署生成的一次性引导凭据或受控本机初始化流程，禁止暴露端口后任何人抢先设管理员；初始化事务化、幂等，凭据不写 URL/公共日志。
4. tokens 新增随机非密 ID、摘要存储、created/expires/revoked/last_used；原 token 只在签发时返回，列表按 ID 撤销；支持撤销其他设备、到期、logout、改密失效策略。
5. 旧 token 迁移为摘要并确定兼容期；不给前端返回完整 token；Web/扩展加入令牌列表/撤销与 401 后处理。
6. 公开分享密码验证与管理员登录分别限流，不共用权限凭证。

**验收**：env/DB 两模式连续错误均 429；伪造代理头不能规避；无引导凭据无法 setup；并发 setup 只有一个成功；列表 ID 可撤销另一个设备；过期/撤销 token 401；数据库备份中无可直接使用的 token 明文。

**交付**：认证流程图、迁移和升级说明、生产语义集成测试。**不做**：多用户注册/OAuth。

### DEV-06：真实 `pageCapture` 与权限修复

**目标/证据**：E09/E10。不能把 base64 猜测或占位探针视作快照已完成。

**实施步骤**：

1. 对照当前 Chrome/Edge 官方 API 与项目 Chrome 类型，确认 `captureMHTML` 回调 Blob、错误与 MV3 可用上下文；删除自定义 string 签名和无依据 atob 兼容分支。若当前 SW 不能安全处理 Blob，采用官方允许的扩展页面/offscreen 编排路径，并记录依据。
2. 清单补所需 `pageCapture`/`scripting` 等最小权限；不为简化开发默认申请全站权限。为用户自定义 NAS origin 配置 optional_host_permissions，保存连接时经用户手势申请，拒绝可重试。
3. 捕获前再次隐私判断；单次调用返回 bookmarkId，不共享 `lastSavedBookmarkId`，防并发串页；读取 lastError，检查 Blob/字节非空和 MIME。
4. 替换探针中 `expect(true)`：从真实 popup 用户点击触发，断言捕获文件/上传记录/净化查看、失败提示。登录页使用本地测试登录站，不用用户真实账号。
5. 更新 `A4-3-pageCapture探针.md`，追加新结论并注明旧 base64 说法被纠正，不涂改旧执行历史。

**验收**：Chrome、Edge 分别覆盖普通/中文/登录测试页/受限页/隐私域；普通与登录页产生有效 MHTML；隐私页捕获调用 0 次；失败无成功记录；同时请求两标签页不串 ID；不支持的浏览器明确提示不支持。

**交付**：真实版本号/权限清单/矩阵/截图与可运行探针。**不做**：以下载原页代替捕获成功。

### DEV-07：快照文件、索引、查看与删除一致性

**目标/证据**：E11。防止内存超限、孤儿文件和“索引存在但不可查看”。

**实施步骤**：

1. 上传读取期间即限字节；校验 multipart/MHTML 实际结构，不能只凭 MIME-Version 接受任意文本；分配快照 ID/幂等键与 uploading/ready/failed 状态。
2. BlobStore 接口集中暂存、校验、原子改名、索引发布；失败清临时文件，重启回收/修复非 ready 状态；文件路径由存储层生成，禁止客户端指定绝对路径。
3. 用户显式删除书签/快照时处理索引、磁盘、配额；删除失败可重试且可观测。合并软归档仍保留关联文件。
4. 查看器隔离脚本/表单/框架/外联，CSP 与 sandbox 配合；MHTML 解析使用可维护解析策略，测试 QP/base64/中文/多段 MIME；原文件仅鉴权受控 attachment 下载。
5. 新增书签快照列表、状态、查看/下载/删除 API；扩展/Web 通过带认证 fetch 或受控短期授权打开，不把 bearer 放查询参数。

**验收**：20MB 超限/chunked 超限在读完前 413；磁盘满、写文件失败、索引失败、进程中止后无永久孤儿 ready 记录；重启可查看；浏览器网络断言外联 0，脚本/表单不执行；删除后空间可回收，软合并再恢复仍可读。

**交付**：BlobStore、生命周期/故障矩阵、查看器真实浏览器证据。**不做**：公开快照、无限保真承诺。

### DEV-08：统一整理提交与撤销事务

**目标/证据**：E12/E13/E19。收件箱、聊天、人工确认使用同一可恢复提交内核。

**实施步骤**：

1. 定义 actionId、稳定 bookmark/folder ID、目标 plannedFolderId、before/after revision。移除以目录名称解析目标的提交逻辑；同名目录要可区分。
2. 网络计算在事务外；提交短事务重查隐私、私密状态、当前父目录、用户 revision、目标存在性。收件箱只有仍在 inbox 且未被人工改动的项允许移动。

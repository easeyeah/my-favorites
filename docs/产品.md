## 1. 产品定位

### 1.1 一句话定位

**当你收藏了几百个网址却再也没打开过它们时，my-favorites 用 AI 把这堆书签变成一个能天天用的个人导航主页。**

### 1.2 唯一核心任务（JTBD）

用户雇佣本产品只做一件事：**"把我失控的书签堆，变成我有掌控感的、每天使用的入口。"**

| 部分 | 角色 | 定性 |
|---|---|---|
| AI 一键整理 + 内容缓存 | **楔子**（为什么选我们） | 核心 |
| 导航站生成 | **产出物**（整理结果的可视化落地，也是日活阵地） | 核心 |
| 一键收藏/收纳盒自动归位 | **留存钩子**（让 AI 介入每一次书签流入） | 核心 |
| 持续死链/查重维护 | **回访理由** + 信任构建 | 核心（当前为手动/定时触发） |
| 多端同步、私密加密 | 服务于闭环的配套 | 后置 |

**判断标准**：新功能必须能回答"它让整理更准、让导航站更有用、或让用户更常回来"三者之一，否则不进路线图。

### 1.3 产品哲学（首页与交互的最高准则）

- **产品替用户干活，不给用户派任务**：首页只有已完成的自动动态（可撤销），不做待办清单；「今日建议」形态已被否决（D37 收口，后经首页哲学再次确认）。
- **功能点化，不做聊天**：AI 能力一律做成「点了就跑」的功能点（D42 已整体下线自由对话）。
- **直接生效 + 可撤销**：整理不设确认流，组织版本是唯一安全面（D27）。
- **最小配置面**：能自动推断的不给配置项；新功能设置面默认压到开关粒度（D41 确立）。
- **删除永不自动执行**：AI 只出建议清单（红线③）。

### 1.4 为什么不是 Raindrop.io

1. 产出物不同——我们落地为**每天使用的导航主页**（占据新标签页），Raindrop 产出仍是"一个更好的书签库"；
2. 交互范式不同——**一键 AI + 内容理解、直接生效、随时撤销**，Raindrop 以手动为主、AI 仅给建议；
3. 数据资产复利——摘要/快照越积越多，整理偏好持续学习，**用得越久越准**；
4. Raindrop 不可自建，我们的自建 Docker 形态在竞品全场空白。

## 2. 竞品与差异化

**Raindrop.io**：全平台、集合/嵌套标签、死链检测（付费）、永久副本（付费）、公开集合、AI 建议分类。弱项：手动整理为主、无导航站产出、不可自建。

**Flomo / Cubox 类**：收藏"内容片段"而非网址入口，不构成直接竞争，验证了 AI 辅助整理的付费意愿。

**Edge 商店参考扩展**：笔点（书签→个人主页，纯手工）、HamHome（BYOK/Readability 本地快照/隐私域名，仅本地无导航站）、BookmarkSync（免 Google 账号同步，无 AI）。

| 能力 | Raindrop | 笔点 | HamHome | **本产品** |
|---|---|---|---|---|
| 内容级 AI 分类 | 建议级 | ❌ | ✅ | ✅ |
| 一键功能点整理（直接生效+撤销） | ❌ | ❌ | 部分 | ✅ 核心特色 |
| 收纳盒自动归位 | ❌ | ❌ | ❌ | ✅ 懒人主路径 |
| 收藏时即时归位建议 | ❌ | ❌ | ❌ | ✅（规则缓存，见 §10 差异①） |
| 产出导航主页（4 模板） | ❌ | ✅ 单一样式 | ❌ | ✅ |
| 死链检测/查重 | ✅ 付费 | ❌ | ❌ | ✅ 免费+可自建 |
| 页面快照（MHTML） | ✅ 付费 | ✅ | ✅ 本地 | ✅ |
| 自建服务端 | ❌ | ❌ | ❌ | ✅ 核心特色 |

> 结论："**流入即归位 → AI 整理 → 导航站 → 持续维护**"的完整闭环无人覆盖。

## 3. 用户画像与 Aha 旅程

- **P1 失控的收藏者（主力）**：书签 200–2000 条，存了从不回访，找不到、不敢删。对复杂交互敏感，默认给最简单路径。
- **P2 效率门户用户**：想要美观的个人起始页，手工建导航站太费时，付费意愿高。
- **P3 自托管极客/NAS 用户**：数据主权敏感，付费意愿低但是口碑节点与自建形态验证者。

```
安装扩展 → welcome 四步引导：一键导入全部书签（30 秒，无需配置）
   → 阶段1 规则引擎直接整理到位（0 token，<15s）+ 结果与目录树预览   ← ★ Aha Moment
   → 设为新标签页
   → 阶段2 内容级精修后台进行（摘要/语义/LLM 归位），通知「已精修 N 条」，可撤销
   → 此后：随手丢进📥收纳盒自动归位、每次收藏即时建议、定期体检
```

**Aha 定义：导入后 60 秒内看到整理结果**。注册和 BYOK 都在 Aha 之后。

## 5. 产品形态总览

当前**唯一交付形态 = 浏览器扩展 + 自建单容器服务端（形态 B）**，Web 管理台由同一服务端托管。

```
浏览器扩展（MV3，用户唯一入口）          自建服务端（Hono + SQLite，单容器）
  background / popup / newtab              ├─ Web 管理台（静态托管 + /api/v1）
  options / welcome / viewer               ├─ 公开导航站 /s/:slug（服务端渲染）
        │  HTTP + Bearer Token             ├─ 整理编排 / 内容摘要 / 语义向量
        └──────────────────────────────►   └─ 定时体检（env 门控，默认关）
```

- **形态 A 官方云 SaaS**：📋 规划中（代码仅有连接页占位常量 `https://cloud.my-favorites.app`，Postgres/pgboss/S3 均未实现）。
- **形态 C 纯本地无服务端**：📋 规划中（D15）；当前未连服务端时仅有离线首屏与受限缓存（D18），不是完整本地模式。
- 应用库是主数据。**未开同步时**浏览器书签是导入源与受控镜像（D16；移动 D20 / 删除 D44 / 重排 D45 单向回写）。**开启 D49 总开关后**升级为双向直接同步：浏览器收藏夹 = 库的实时视图，增删改移序自动收敛。

#### 6.1 自动收纳（F1.5）现状规格

- **投递口**：浏览器书签栏的「📥 收纳盒」原生文件夹（旧名「📥 自动整理」setup 时幂等改名）；支持放在书签栏或「其他书签」下。原生下拉不可定制、文件夹无角标 API——文件夹只做物理投递口。
- **进入方式**：浏览器原生拖入、右键「收藏到收纳盒」、popup「不想了，先丢收纳盒」。
- **触发链路**：background 监听收纳盒直属节点 onCreated/onMoved（mirrorGuard 防循环）→ 持久队列（storage.local `mfPendingOps`，SW 重启不丢）→ 1.2s 防抖 → 先 `/inbox/map` 建身份映射 → 再 `/inbox/process` 走两阶段流水线（规则即归位；未命中进 LLM 内容级分类）→ 成功后消费浏览器镜像操作。
- **状态机**（inbox_state 表）：pending / classifying / placed / ambiguous / privacy_hold / retry（最多 5 次）/ no_llm（未配置 AI 时留箱）。
- **歧义处理**：不再有"集中询问"会话——popup 收纳盒视图里**每条歧义内内联下拉选目录**（显示"AI 倾向「X」"）；隐私条目内联手动选目录 +「按域名记忆」（写入本地规则）；retry 条目内联重试按钮。
- **镜像模式（D20）**：归位 = 浏览器节点真的移入书签栏「mf-整理/<目录名>」（持久待执行队列 pending_browser_ops，不与 DB 事务耦合；DB 提交与镜像入队同事务）。
- **清扫兜底**：🚧 扩展无 chrome.alarms 定时器；服务端整点清扫受 `MF_MAINTENANCE_INTERVAL_HOURS` 门控（≤0 不注册，即默认关，compose.full 默认 168）；可靠入口是 options「立即清扫」与收纳事件触发。
- 用户手动移出收纳盒 = 已确认，AI 不再动；所有移动写 organize_version 可撤销；隐私域名条目仅存 URL、只人工归位。

## 7. 浏览器扩展功能规格（MV3 / WXT）

六个 entrypoint（无 sidepanel、从未有 offscreen）：

### 7.1 background（Service Worker，事件中枢）

- 收藏主链路：隐私门 → activeTab 注入抓取 → POST /bookmarks → 二次隐私门 → POST /content/capture → 页内 toast（4s，非重复收藏带「撤销」=删书签）→ 可选 MHTML。
- 收纳盒文件夹幂等创建/改名/换父目录；收纳盒事件监听 + 持久队列 + 防抖 flush（§6.1）。
- 浏览器镜像消费（device.ts）：拉 /browser/ops 逐条执行 move / remove / reorder 并回执 done/failed/cancelled；5s mirrorGuard 防循环；清理历史空壳「mf-整理」文件夹。
- 右键菜单三项：⭐ 收藏到 my-favorites（page/link）、📥 收藏到收纳盒（page/link）、📸 给当前页拍快照（仅 page）。
- 快捷键：quick-save = Ctrl/⌘+Shift+S。
- 角标：归位「归位N」（silent 档不显示，5s 清）、快捷键失败闪「×」、每日首启体检角标。
- 消息路由：save-current / undo-bookmark / save-to-inbox / setup-inbox / sweep-inbox / snapshot-current / **sync-set / sync-now / sync-status**（D49）；旧 import-bookmarks / sync-mirror / reorder-browser 随总开关退役。全程 try/catch 防 popup 卡死。
- 安装/每日首启同步隐私规则；onInstalled 首次安装打开 welcome。

### 7.2 popup（工具栏气泡，320×518，**单面无页签**，D46）

- 顶栏：品牌图形标 + ⚙ 进 options。
- 页面信息卡：真实 favicon（失败回退首字母色块）+ 标题 + host。
- 隐私前置：打开即判定 read_content，命中显红条「仅存 URL，手动选目录」（三原因码：隐私域名/私密书签/策略未加载）。
- 主按钮两态：命中建议「✓ 收藏到「X」」/ 未命中「✓ 收藏，交给 AI 归位」（§10①路径 bug）。
- 收纳盒视图（有才显示）：pending/retry/ambiguous/privacy_hold 各态条目内联处理。
- 最近自动归位（每条带撤销）+ 最近整理版本（取 8 显 3，可回滚）。
- 底部折叠区：快照开关（默认开、可记忆）、备注、改目录、「先丢收纳盒」。

### 7.3 newtab（新标签页，D40 极简 + D41 小组件）

- 固定核心区：居中品牌标 → 时钟日期（15s 刷新）→ 胶囊搜索框 → 最常访问磁贴。**核心区位置恒定，任何小组件不得挤开搜索框。**
- 搜索：书签引擎常驻（结果就地展开，点击上报 /bookmarks/:id/click）；外部引擎 chips 百度/必应（默认开）/Google（可选）；裸 URL 直接打开；空查询 Tab 循环切引擎。
- 最常访问：/bookmarks/top?limit=24，按**应用内点击计数**（非浏览器历史，冷启动为空自然隐藏）。
- 自定义面板（右下 ⚙️）仅三项：常用区数量 4/8（默认）/12/16/关闭；外部引擎多选；小组件显隐 chips。无其他配置。
- 小组件（注册制，出厂全关，用户只有显隐权）：公网 IP（四源并行探测+择优、点击 v4/v6 切换带记忆、浏览器直连）、天气（IP 归属地自动定位，wttr.in 主/Open-Meteo 备）、黄历（lunar-typescript 纯离线）；**无卡片盒子，全部内联页脚两行字层**（黄历一行；天气·IP 一行；次级信息退 hover）；仅「宜」「忌」二字着色（绿 80%/红 70%，newtab 唯一用色）。

### 7.4 options（设置页，原生 DOM 单页分区卡，无 React）

八张卡 + 一张灰置预留卡：①服务端连接（含 /healthz 测试，localhost 失败自动回退 127.0.0.1；**「打开管理台」按钮——新标签页深链 `serverUrl/#overview`，用户反馈补齐的管理台入口**）②鉴权（管理员密码换 token）③收藏夹双向同步（**单一总开关「与浏览器收藏夹同步」默认关 + 立即同步 + 状态行 + 大批量删除确认**，D49；取代旧一键导入/反向同步/重排/同步删除四入口）④收纳盒（建盒/投递口位置/立即清扫；⚠️ 卡内"攒≥3条集中询问"为过期文案 §10⑤）⑤整理通知三档 ⑥隐私保护说明卡（含"私密仅隐藏无加密"声明）⑦服务端概览（/stats）⑧关于（版本/AGPL/当前模型只读）；灰置卡=本地模式预留。

### 7.5 welcome（安装后四步引导）

① 选导入方式（读书签树【推荐，显本机计数】/ HTML 文件，含隐私说明）② 分批导入进度条 ③ Aha：阶段 1 规则引擎整理结果（0 token，统计卡 + 改动明细 + 目录树预览 + "阶段 2 后台进行"提示）④ 设为新标签页 + **打开管理台** + 三张用法引导卡。

### 7.6 viewer（快照查看器）

`?bookmarkId=` 进入：左栏快照版本列表，右栏 iframe srcdoc 渲染服务端净化 HTML；明示「仅你可见，公开导航站永不展示」。

## 10. 已知实现差异（文档不粉饰，清理自代码盘点）

> 原则：文档如实记载半成品与漂移；修复另开切片，不在文档里假装已完成。

1. **popup 即时建议路径 404（活 bug，HEAD 已存在）**：popup 调 `POST /api/v1/pipeline/suggest`，服务端实际注册的是 `/bookmarks/suggest`；失败被 `.catch(() => null)` 静默吞掉，导致真实环境下「✓ 收藏到「X」」缓存命中态从未出现，主按钮恒为"交给 AI 归位"。?mock/单测都没覆盖到这个错配。修复=改一端路径并加跨端契约测试。
2. **通知 card 档半成品**：双端设置均可选 card，但管理台 tidyNotify 与扩展 background 都只区分 silent/非 silent，无摘要卡 UI，选 card 等同 toast。决策：补 UI 或砍档位。
3. **"维护周报"名实不符**：无周报生成 job；扩展每日首启角标与 options 文案沿用"周报"字样，数据源是 /health-report 体检 JSON；F5.5 宣称的周期升级/复活检测/失败原因落库大多未实现。
4. **站点化投影无 UI（F4.7）**：后端三类标注/重建/钻取端点齐全，web 无任何入口，siteType 查询参数无调用方，「包含资料站」开关未接线。
5. **options 过期文案**：收纳盒卡仍写「歧义阈值 80% · 攒 ≥3 条集中询问」，D42 后实际是 popup 条目内内联下拉，无集中询问。
6. **令牌管理界面缺失**：/auth/tokens 列表/吊销/logout 端点齐全，设置页只有登录/退出，无令牌列表。
7. **模块开关仅前端一半**：lib/modules.ts 只在 localStorage 隐 navsite 页签；ai 开关无门控；服务端路由无条件全挂载、定时任务不感知模块（「模块化切片」未做）。
8. **清扫调度默认关**：服务端整点清扫与维护调度共用 MF_MAINTENANCE_INTERVAL_HOURS 门控，默认 0；扩展无 alarms；开箱后收纳盒兜底清扫实际不跑（compose.full 设 168 才随周任务启用）。
9. **Anthropic 预设不可用**：providers.json 有 anthropic（apiStyle=anthropic），但 llm-client 只实现 OpenAI 兼容 /chat/completions（拉模型列表兼容两种协议），选用后对话调用不通。
10. **provider 预设三个 BaseURL 待核实**：MiniMax、小米 MiMo、腾讯 TokenHub 的 baseUrl 为 null（TODO_VERIFY），添加时不预填；腾讯无模型、疑似订阅型网关，倾向移出。
11. **快照查看无 mock 分支**：?mock 演示模式下书签详情点「查看快照」会真实 fetch 而失败。
12. **手动批量移动不进 organize_version**：管理台批量移动是逐条 PATCH /bookmarks/:id，不写整理版本、不可整批撤销（与 F1.3 旧文档"记入版本可回滚"的说法不符）。
13. **includeRef 配置悬空**：NavSiteConfig 类型有 includeRef 字段，界面无开关。
14. **死代码残留**：web 的 Card/Stat/PageHeader/FeedbackBar/isoWeek、ui/card.tsx、ui/sheet.tsx 无引用；inbox 仍是路由白名单但无页面无导航（D37 独立页签回滚后的残留）。
15. **/crawl/run 无调用方（D62 盘点）**：服务端补抓端点齐全（guardedFetch 500KB），web/extension 均无入口，仅 mock 有模拟——死端点；D61 已把补抓成功接入资料库物化（抓到即入库），但「谁来调 crawl」仍在：清理或给管理台补「补抓选中项」入口（资料库后手）。
16. **视频作者/时长未捕获（D61）**：资料库视频条目现仅封面（og:image）+来源；作者/时长需要 og:video:duration 或站点特定解析，后置到资料库后手。存量回灌零封面（封面由后续捕获增量补齐）。

> 撤销登记：原第 15 条「收藏响应被内联摘要阻塞」系 D62 盘点误判——async 模式 `maybeSummarize` 本就 `void run()` 不阻塞响应，真缺口是无兜底补扫，已由 D63 修复（常驻补扫 + call_model 拒绝留痕），不再列为差异。

## 11. 路线图（能力切片 · Now/Next/Later · D34）

> 进度 = 已验收切片数；无工时、无百分比。每片纵切 UI→API→数据，自带验收标准。

**🎯 Now（当前焦点，一次一个主目标）**

- **资料库后手（D61 延伸）**：视频作者/时长元数据捕获（§10⑯）；`/crawl/run` 补管理台入口或清理（§10⑮）；笔记应用导出适配器（Notion 优先，Obsidian 目录落盘次之）。

| 层 | 定价（规划） | 内容 |
|---|---|---|
| Free | ¥0 | 收藏/收纳/整理/导航站；BYOK 下 AI 完整体验免费；云端 L1+L2+快照小配额；行为配额（如每月 3 次全库整理）而非容量配额 |

**North Star：周活跃导航站使用**（本周 ≥3 天通过导航站/新标签页访问书签的用户）。

| 指标 | 目标 |
|---|---|

| 收纳盒归位 7 日回滚率 | ≤20% |

## 13. 风险与合规

| 风险 | 对策 |
|---|---|
| 商店审核（书签+抓取高敏权限） | 权限最小化（activeTab 点击注入，host_permissions 仅本地）；隐私政策提审前就绪；Edge 先提审 |
| 抓取与快照版权 | 快照仅用户私有；公开导航站只出元数据+摘要且仅限显式发布集合；公开站永不展示快照内容（红线④） |
| 云端隐私悖论 | 隐私五动作前置校验在 packages/shared 内（架构上不可绕过）；银行/内网内置清单 |
| 公开导航站滥用 | 随机 slug 不做广场、不做公开检索；敏感内容不进公开投影（D43） |
| 死链误判 | 三级判定保守策略，疑似只标注，建议措辞不自动执行 |
| AI 整理翻车 | act+undo + 7 日回滚率监控；歧义不强移；冲突跳过回原因码 |
| 供应商审核拒收 | 敏感词表事前旁路 + 审核错误二分隔离（D43） |
| Webhook 外发 | 隐私命中永不外发；HMAC 签名；SSRF 守卫；不内置下载器模板（D33） |

**硬性红线（违反=PR 不通过）**：见根 [AGENTS.md](../AGENTS.md) 开头五条（NAS 资源 / 隐私不可绕过 / 删除不自动且移动可撤销 / 公开站版权 / 导入不进收纳盒）。

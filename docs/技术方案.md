## 1. 技术选型（现状）

| 层 | 现状 | 说明 |
|---|---|---|
| 仓库 | pnpm + turbo monorepo，TS 全栈，Node ≥22 | |
| 扩展 | Manifest V3 + WXT + React 19 + Tailwind v4（options 页例外：原生 DOM） | 六个 entrypoint，见 §6 |
| 服务端 | Hono（@hono/node-server，Node runtime） | 无框架 ORM；SQL 集中在 `apps/server/src/store.ts` 仓储层 |
| 数据库 | **node:sqlite 内置驱动**（DatabaseSync，WAL + foreign_keys） | owner 主库 + 每用户独立 SQLite 文件；迁移 v1–v18 见 §4.2 |
| 队列 | **无通用队列框架**：浏览器镜像 = SQLite 表 `pending_browser_ops`；后台任务 = setInterval | 📋 云端形态规划 pgboss，无 JobQueue 抽象（不引入 Redis） |
| 正文提取 | **无 Readability/linkedom 依赖**：扩展注入脚本取 `innerText`（截 2 万字）；服务端正则取 meta + HTML 粗取正文（截 500KB/20KB） | 技术方案旧版所称 linkedom + @mozilla/readability 从未引入 |
| LLM | `packages/ai` 自研：OpenAI 兼容 /chat/completions + /embeddings；30s 超时；零依赖 fetch | Anthropic 协议仅模型列表兼容、对话未适配（产品.md §10⑨） |
| 向量 | content_cache.embedding（JSON 数组）+ 内存余弦；≥50 条触发 k-means-lite 聚类 | 📋 sqlite-vec/pgvector 未引入 |
| 校验 | zod（边界 schema 在 packages/shared，服务端复用） | |
| Web 管理台 | React 19 + Vite + shadcn/ui（源码入库）+ Tailwind v4 | 构建产物 web-dist 由服务端白名单静态托管 |
| 公开导航站 | 服务端 Hono 直接渲染（`apps/server/src/nav.ts`，原生 CSS 模板），不在 web 工程内 | |
| 对象存储 | 📋 无；快照/图标落本地磁盘（DATA_DIR/snapshots） | 云端 S3 为规划 |
| DOM/快照消毒 | 自研 snapshot-view.ts（MHTML 解析 + 白名单清洗 + CSP 壳） | |

### 1.1 选型原则

1. NAS 约束优先：运行内存 <300MB、镜像 ≤250MB、单文件存储、ARM64；
2. AI 开发友好：单一 TS 语言栈、强类型、领域逻辑全栈共享；
3. 一套领域逻辑服务三种形态（当前只交付自建端，云/纯本地为规划）。

### 1.2 已记录的实施偏离

| 项 | 早期方案 | 实际 | 结论 |
|---|---|---|---|
| SQLite 驱动 | libsql | node:sqlite 内置 | 零原生依赖、esbuild bundle 兼容、ARM64 风险低（A3-1） |
| ORM | Drizzle | 手写 SQL 仓储层 | ORM 后置到云端引 PostgreSQL 时再评估 |
| 正文提取 | linkedom + Readability | innerText / 正则粗取 | 随 F2 质量验证再决定是否引入（评测：提取失败率 >15% 再换） |
| JobQueue | SQLite/pgboss 同一接口 | pending_browser_ops + setInterval | 抽象待云端形态需要时再做 |
| 向量库 | sqlite-vec / pgvector | 内存余弦 + JSON 存储 | 单用户千级条目足够，无外部依赖 |

## 3. 系统架构

**当前交付：形态 B 单容器自建端**。扩展经 HTTP + Bearer Token 连服务端；服务端进程内同时承担 API、定时任务、公开站渲染、静态托管。未连接服务端时扩展仅 D18 受限离线能力。

```
[扩展 SW/popup/newtab/options/welcome/viewer]
        │  /api/v1（Bearer；CORS 白名单；扩展 origin 非生产放行）
        ▼
[Hono API]── store.ts ──[SQLite WAL]
    ├── Pipeline/OrganizeService ── @mf/ai ── LLM 端点（BYOK/env/mock）
    ├── SemanticService（内存余弦）/ SiteAnalysis（投影缓存入 prefs）
    ├── setInterval 调度（维护 + 收纳盒清扫，同受 MF_MAINTENANCE_INTERVAL_HOURS 门控）
    ├── pending_browser_ops（扩展轮询消费：move/remove/reorder）
    ├── hooks.ts（出站 Webhook，HMAC + 退避 ×3）
    ├── guardedFetch（crawl/favicon/死链共用出站守卫）
    └── /s/:slug 公开导航站 + web-dist 静态托管
```

📋 形态 A 的 SaaS 运营栈（Postgres + S3 + pgboss + 独立 Worker + 计费）与形态 C（纯本地：IndexedDB + BYOK 直连 + 静态 HTML 导航导出）仅为架构预留，代码不存在。**统一登录、多用户隔离与系统管理已实装（D73），官方云只是同一系统的托管部署地址。**

| `schema_migrations` | 迁移水位 |

设计要点：
- 无 tag 表（标签在 content_cache.l1_tags JSON）；无 FTS5 虚表（全文=LIKE）；无 job/job_run/usage 表（旧文档虚构）。
- URL 键**保守规则 v2**（D22）：保留 scheme/www/fragment/端口/业务参数，仅删 28 个经验证 tracking 参数，剥 userInfo，路径编码归一+去尾斜杠；similarKey 仅供疑似建议。
- merge = 软归档：被合并方 archived_into 指向保留方（added_at 最早、平局 id 字典序决胜），缓存/快照/私密位全保留。
- 整理动作：move / createFolder（plannedFolderId 映射）/ merge / markPrivate；rename 类型预留无产生点。

### 4.2 迁移版本

v1 基线 17 表 → v2 软归档/乐观锁/会话基线 → v3 设备身份+镜像队列 → v4 保守 URL 键重算（出迁移报告）→ v5 导航显式发布集合（存量站点转待确认）→ v6 令牌摘要化（旧 bearer 失效）→ v7 undo 版本+快照删除台账 → v8 site_type/nav config/hook/inbox_state/bookmark_click → v9 audit_log（D58 操作审计）→ v10 material（D61 资料库；启动时一次性存量回灌，prefs 记完成位）→ v11 material.category（D65 资料自有 AI 两级分类；backfillCategories 涓流回灌常驻）→ v12 multiuser_accounts（D67 统一账号内核：users + tokens.user_id + public_slugs；每用户独立 SQLite 文件跑同版迁移）→ v13 system_admin_and_user_status（D73：users.role/disabled_at；owner 或无 owner 部署的最早账号自动成为管理员）→ v14 placement_review（D77：inbox_state.reviewed_at 一次性复核标记）→ v15 sync_protocol（目录身份/根映射/回执/库代际）→ v16 folder_revision（目录乐观修订）→ v17 material_convert（D91：书签资料生命周期字段、版本标签/转换版本引用与持久识别候选；历史行默认不转换）→ v18 organize_task（D92：organize_task / organize_task_item 持久整理任务与逐条基线；material.category_revision/category_source 分类写入 CAS 与来源；organize_version.task_id/task_batch 任务关联）。

**保留裁剪（D58，常驻不依赖调度开关）**：`startRetentionPrune`（maintenance.ts）启动即跑 + 每日一次——changes 14 天（离线设备漏拉由 treesDiffer catch-up 全量对齐兜底）、events 90 天、idempotency 7 天、audit_log 最近 1000 条、**整理任务明细 30 天 / 每库最近 20 次（D92：到期先原子禁用「继续」再裁剪逐条明细与计划；版本事实不裁剪，历史版本的撤销入口不失效）**。

**L1 摘要兜底补扫（D63，常驻不依赖调度开关）**：`startSummaryBackfill`（maintenance.ts）启动即跑 + 每 30 分钟一次——候选=有正文（≥40 字）缺 L1 且失败原因非 `privacy_*`（`llm_unavailable`/`stale_policy_discarded` 可重试）；每次最多 5 条涓流踢 `maybeSummarize`（内部现行隐私判定兜底）；无 LLM 配置零开销跳过。兜住 fire-and-forget 摘要的两类永久缺失：进程重启丢在途、LLM 当时不可用。

**备份**：仅在有待应用迁移时执行——`VACUUM INTO` 输出 `DATA_DIR/backups/pre-migrate-v<n>-<ts>.db`（失败兜底 checkpoint+文件复制）。**无定时备份任务**（旧文档所称"内置定时 VACUUM"不实）；设置页展示备份分片用量、保留约 14 份。

## 5. HTTP API（v1 全量清单）

统一前缀 `/api/v1`（Hono 子应用）；根应用承载 /healthz、/auth/login、/auth/register、/s/*、静态文件。鉴权中间件保护整个 /api/v1（见 §9）——D67 起令牌解析后以 AsyncLocalStorage 建立用户上下文，Store.db 按上下文解析数据文件。

### 5.1 书签/目录/导入导出

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /bookmarks/ingest | 扩展批量导入（≤2000 条/请求，幂等键，可选 deviceId+browserId 建身份；不进收纳盒） |
| POST | /bookmarks/ingest/html | Netscape HTML 导入 |

| GET/POST/PATCH/DELETE | /folders(/tree/:id) | 目录 CRUD（仅删空目录、系统目录保护） |

## 6. 浏览器扩展架构（MV3）

**manifest 权限**：`bookmarks, activeTab, contextMenus, storage, unlimitedStorage, scripting, tabs, pageCapture`；命令仅 quick-save（Ctrl/⌘+Shift+S）；host_permissions 只固定 localhost:3000/:3007（云端/NAS 由用户填地址，📋 optional host 动态申请未见实现）。无 sidePanel/offscreen 权限。

**MV3 对策**：SW 被杀死靠 bookmarks 事件唤醒 + storage 持久队列（mfPendingOps、镜像 ops 服务端确认才出队）；activeTab 点击瞬间注入，避免全站 host；SW 内消息路由全程 try/catch 回包。

**关键模块**：
- `lib/api.ts`：ExtensionConfig（serverUrl 默认 127.0.0.1:3000、token、notifyStyle、inboxParent、syncDeleteToBrowser 等）、Bearer fetch、埋点白名单、DTO。
- `lib/device.ts`：mfDeviceId UUID + /devices/register；镜像 ops 执行（move 入 mf-整理；reorder 按实际父节点分组就地排序不搬家；remove 仅删叶子、开关关时回执 cancelled）；空壳文件夹清扫。
- `lib/privacy.ts`：规则本地缓存四态 unknown/fresh/stale/error（24h，按服务端 origin 隔离），仅 fresh 放行五动作，未加载一律保守拒绝。
- `lib/import.ts`：书签树扁平化（跳虚拟根、仅 http(s)、标题截 200、深度 ≤16）。
- popup 单面化（D46）：无页签；收纳盒状态条目内联处理；详见产品.md §7.2。
- newtab/widgets：§7.3 同产品文档；取数在 src/widgets/fetchers.ts（IP 四源/天气双源/TTL 缓存，零新增权限）。
- 入口样式表（`panel.css` / `popup.css`）：Tailwind v4 只用标准 `@import 'tailwindcss';`——自动扫描基路径默认 = Vite root（WXT 项目根 `apps/extension`，不取 CSS 文件所在目录），原先的 `source('../../')` 与之完全重合且属非标准语法（VS Code 内置 CSS 校验报 `css-colonexpected`「需要冒号」，且该 parse 错误没有 `css.lint.*` 开关可精准抑制）。约定：构建在包目录内执行（pnpm/turbo 天然满足）；若将来确需显式基路径，用 `source(none)` + 显式 `@source` 登记，并只配 `"css.lint.unknownAtRules": "ignore"` 压制未知 at-rule（勿动 `css.validate` 总闸）。

## 8. 关键流程

**浏览器模型参照与身份约束（D87 补充）**

Chrome / Edge 的 `BookmarkTreeNode` 用 `id` 标识节点，用 `parentId` 表达树关系，`title` 仅为显示文本。节点 ID 在当前浏览器配置文件内唯一，并跨浏览器重启保持；它不是跨设备的全局 ID。重命名和移动是修改原节点的属性/父关系，而不是按新名称重新查找一个节点。相同父下允许多个同名目录，完整的名称路径也可能相同，不能用作唯一键。字段依据：已安装的 Chrome API 类型定义 `apps/extension/node_modules/@types/chrome/index.d.ts` 中的 `BookmarkTreeNode`。

本项目在这个模型上增加跨端映射：

| 角色 | 身份 | 可变属性 |
|---|---|---|
| 浏览器目录 | 扩展设备/安装标识 + `browserFolderId` | `title`、`parentId`、顺序 |
| 管理台目录 | 当前用户库内的 `folders.id`（UUID） | `name`、`parent_id`、顺序 |
| 两端对应 | `folder_identity(device_id, browser_folder_id) → app_folder_id` | 只能经确认回执或带前置条件的显式修复调整 |

核心不变量：**名称不是主键，路径不是主键；同一设备中不同的当前活目录不能指向同一个库目录。** 不同设备可以各有一个节点映射到同一个库目录，不能把浏览器局部 ID 直接当作服务端全局 ID。名称/父关系只辅助首次一对一认领；一旦建立映射，后续增改移序、放置与恢复均以稳定 ID 为准，不再因重名重新选择目标。这里的“活目录单射”由完整浏览器树与身份写入校验执行；保留历史死亡 ID 或旧折叠记录时，不能不经核验直接增加数据库唯一约束或批量清映射。

例如以下为**示例 ID**，三个同名目录必须对应三个库实体，而不是名称去重：

```text
浏览器 b101（项目） ──→ 库目录 a001（项目）
浏览器 b102（项目） ──→ 库目录 a002（项目）
浏览器 b103（项目） ──→ 库目录 a003（项目）
```

## 9. 安全设计

- **隐私不可绕过（红线②）**：五动作校验在 @mf/shared 引擎内；扩展端策略未加载保守拒绝（四态缓存）；服务端调用前校验 + LLM 返回后比对 revision 重验，过期丢弃（stale_policy_discarded）；embedding 前后双验。
- **鉴权与系统管理统一（D73）**：一切部署共用 /auth/register 与 {username,password} 登录；无用户名的旧 {password} 仅作 owner 兼容。旧单管理员启动或首启 setup 时自动 provisioning username='admin' 的 owner；全新部署首个注册账号自动成为 admin，后续默认 user。setup 门槛=生产语义+无管理员+无注册用户；owner 改密双写 users 行与 admin_password_hash，env 密码仍由部署配置管理。v13 增 role/disabled_at：管理接口逐请求校验 isAdmin，普通用户 403；停用/重置密码撤销目标全部令牌，owner/当前管理员不可停用或降级，至少保留一位可用管理员。registration_open 持久化在主库 settings，MF_REGISTER_OPEN 仅为未设置时的初始默认值，healthz 公开 registrationOpen。dev/test 无密码时仅「未携带令牌」可匿名 self；坏令牌/撤销令牌/停用令牌一律 401，不再降级成 owner。**多租户隔离=每用户独立 SQLite 文件**（owner=self 恒主库，其余在 DATA_DIR/users/<id>/my-favorites.db，注册即建库跑同版迁移），tenancy.ts AsyncLocalStorage + Store db 解析器实现按请求路由，仓储层 SQL 零改写。UserDbManager 上限 maxOpen=256 + 闲置 10 分钟回收（当前上下文库跳过），打开句柄数随活跃用户而非注册用户增长；跨用户共享面（users/令牌/部署设置/认证审计/public_slugs）集中 registry.ts 落主库；SSE 按 user 过滤、后台任务跳过停用用户、nav HMAC 密钥部署级共享。
- **令牌**：32 字节随机，仅存 SHA-256 摘要 + token_id，默认 30 天，可按 ID 撤销/logout；列表不回可复用凭据；registry（主库）按 user_id 隔离「我的令牌」。D84 列表增 current 布尔标识（从请求 Bearer 解析）；POST /auth/tokens/revoke-others 必须持有效当前令牌，按 user_id 限定且排除当前 token_id，仅撤销有效会话，落单条汇总审计。管理台过滤失效项、当前会话优先并按最近使用排序，每页 10 条客户端分页，批量撤销先确认；不按 label 合并真实设备。
- **管理表格交互（D85）**：`NumberedPagination` 统一页码分页（总数/首尾/当前窗口/省略号/边界禁用），用户列表与登录会话 10 条客户端分页，日志 25 条服务端分页；`.data-row` 统一 hover/focus-within 高亮，行内及分页按钮统一 `size="xs"`（28px），顶部仍用 sm；行分割线独立于圆角背景。规范详见 AGENTS.md，其他存量列表后续触及时迁移。
- **限速**：内存滑窗 5 次/60s/key（admin-env/admin-db/nav 分 key，MF_TRUST_PROXY=1 才信 XFF）。
- **Key 加密**：AES-256-GCM（scrypt 派生 MF_SECRET_KEY，密文 v1:iv:tag:ct）；生产无 ≥16 字符主密钥保存 Provider 直接报错；列表永远 ********。
- **SSRF 守卫（fetch-guard.ts）**：运行时可注入 cloud/selfhosted_strict/allowlist 三模式；环境配置对一切部署统一默认 selfhosted_strict，仅 MF_ALLOW_INTRANET_FETCH=1 显式切 allowlist，MF_FORM 不再改变网络安全行为。禁段覆盖私网/链路本地/CGNAT/IPv6 ULA 等；DNS 后连接固定校验 IP；重定向逐跳重校验+跨主机剥凭据头；字节上限与总超时。crawl/favicon/死链/Hook 共用；管理员配置的 LLM 端点不套 SSRF。
- **可见性边界**：X-MF-Private:1 才可见私密（公开入口永不传）；/content 私密 404；关键词/语义/导出/目录计数同边界；公开站仅显式发布集合内非私密非软归档项。
- **快照**：净化 script/iframe/object/embed/form/外链/on*/javascript:/data: URL，CSP default-src 'none'；无法消毒给下载而非强显；下载 nosniff+attachment。
- **CORS**：MF_ALLOWED_ORIGINS 白名单；非生产额外放行 localhost 与扩展 origin；允许头含 Authorization/Idempotency-Key/X-MF-Private/X-MF-Device。**跨源管理台接入**：全部数据请求跟 cfg.serverUrl 走，统一登录页地址输入可指向任一已放行页面 origin 的服务端；主路径仍是「打开谁的地址就管谁」（同源零配置），跨源接入是显式放行后的能力。
- **静态托管**：仅 /assets、/brand、/providers + 根 index.html 白名单（path.resolve 防穿越，MIME 白名单，缓存分级）；/favicon.ico 固定 204。
- **日志**：只打方法+路径模板+状态+耗时，不打 query。

### 10.2 Docker 与运行形态

- `docker/docker-compose.dev.yml`：构建 dev 目标，bind mount 源码 + llm-mock 服务（默认 LLM 走 mock，CI 稳定）；切本机 Ollama 或真实端点只改 LLM_BASE_URL。
- **可选第二实例联测（D73）**：`docker compose -f docker/docker-compose.dev.yml --profile multi-instance up -d` 额外启动 `server-secondary`（http://127.0.0.1:3100，独立卷 secondary-data）。它与主实例使用完全相同的镜像、环境语义、登录和系统管理，仅地址与数据卷不同，不代表第二套部署；用于多实例/跨地址验证。生产环境的扩展 CORS 走 MF_ALLOWED_ORIGINS 白名单。
- `docker/docker-compose.full.yml`：自用/演示全功能（维护周期 168 等）。
- 生产 Dockerfile 多阶段：server 以 esbuild bundle 交付，运行层禁整包 node_modules（红线：内存 <300MB、镜像 ≤250MB、ARM64）；CI 镜像冒烟断言。
- 迁移启动自动执行、仅前进；待迁移时自动 VACUUM 备份。云端↔自建迁移走 JSON 全量导出/导入。

## 12. 开发工作流

```bash
pnpm install                                   # 装依赖
docker compose -f docker/docker-compose.dev.yml up   # 服务端（必须在 Docker 跑）
pnpm --filter @mf/extension dev                # 扩展 HMR（连 http://localhost:3000）
pnpm --filter @mf/web build                    # web 改动需构建（tsx watch 对 bind mount 失效；改 server 需 docker restart）
pnpm test                                      # turbo 全量单测/集成
pnpm --filter @mf/e2e test                     # Playwright（扩展改动先重新构建）
pnpm seed                                      # 边界情况书签集
pnpm changeset                                 # 功能合入：登记发布说明，提交 .changeset/*.md
pnpm run version                               # 发版：消费 changeset，升包版本 + 生成各包 CHANGELOG.md
pnpm changeset:status                          # 查看相对 main 尚未发版的变更
```

LLM 三档：llm-mock（默认）→ 本机 Ollama → 真实端点，只改 LLM_BASE_URL。

提交：Conventional Commits（commitlint 强制）；**changeset 是版本与 CHANGELOG 的唯一来源**——功能 PR 触发 `apps/*/src`、`apps/extension/entrypoints`、`packages/*/src`、包清单或 `docker/` 时必须新增 changeset（CI `pnpm check:changeset` 门禁，发版 PR 用 `[skip changeset]` 放行），`.changeset/*.md` 与 `config.json` 必须入库；发版后按 `<app>-vX.Y.Z` 打 tag（CI 监听 `server-v*` / `extension-v*` / `web-v*`）；DB 迁移只前进；功能变更必须回写本文档与产品.md（新决策追加决策记录.md）。

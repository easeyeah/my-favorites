## 1. 技术选型（现状）

| 层 | 现状 | 说明 |
|---|---|---|
| 仓库 | pnpm + turbo monorepo，TS 全栈，Node ≥22 | |
| 扩展 | Manifest V3 + WXT + React 19 + Tailwind v4（options 页例外：原生 DOM） | 六个 entrypoint，见 §6 |
| 服务端 | Hono（@hono/node-server，Node runtime） | 无框架 ORM；SQL 集中在 `apps/server/src/store.ts` 仓储层 |
| 数据库 | **node:sqlite 内置驱动**（DatabaseSync，WAL + foreign_keys） | 单文件 `DATA_DIR/my-favorites.db`；迁移 v1–v8 见 §4.2 |
| 队列 | **无通用队列框架**：浏览器镜像 = SQLite 表 `pending_browser_ops`；后台任务 = setInterval | 📋 云端形态规划 pgboss，无 JobQueue 抽象（不引入 Redis） |
| 正文提取 | **无 Readability/linkedom 依赖**：扩展注入脚本取 `innerText`（截 2 万字）；服务端正则取 meta + HTML 粗取正文（截 500KB/20KB） | 技术方案旧版所称 linkedom + @mozilla/readability 从未引入 |
| LLM | `packages/ai` 自研：OpenAI 兼容 /chat/completions + /embeddings；30s 超时；零依赖 fetch | Anthropic 协议仅模型列表兼容、对话未适配（产品.md §10⑨） |
| 向量 | content_cache.embedding（JSON 数组）+ 内存余弦；≥50 条触发 k-means-lite 聚类 | 📋 sqlite-vec/pgvector 未引入 |
| 校验 | zod（边界 schema 在 packages/shared，服务端复用） | |
| Web 管理台 | React 19 + Vite + shadcn/ui（源码入库）+ Tailwind v4 | 构建产物 web-dist 由服务端白名单静态托管 |
| 公开导航站 | 服务端 Hono 直接渲染（`apps/server/src/nav.ts`，原生 CSS 模板），不在 web 工程内 | |
| 对象存储 | 📋 无；快照/图标落本地磁盘（DATA_DIR/snapshots） | 云端 S3 为规划 |
| DOM/快照消毒 | 自研 snapshot-view.ts（MHTML 解析 + 白名单清洗 + CSP 壳） | |

### 1.1 选型原则

1. NAS 约束优先：运行内存 <300MB、镜像 ≤250MB、单文件存储、ARM64；
2. AI 开发友好：单一 TS 语言栈、强类型、领域逻辑全栈共享；
3. 一套领域逻辑服务三种形态（当前只交付自建端，云/纯本地为规划）。

### 1.2 已记录的实施偏离

| 项 | 早期方案 | 实际 | 结论 |
|---|---|---|---|
| SQLite 驱动 | libsql | node:sqlite 内置 | 零原生依赖、esbuild bundle 兼容、ARM64 风险低（A3-1） |
| ORM | Drizzle | 手写 SQL 仓储层 | ORM 后置到云端引 PostgreSQL 时再评估 |
| 正文提取 | linkedom + Readability | innerText / 正则粗取 | 随 F2 质量验证再决定是否引入（评测：提取失败率 >15% 再换） |
| JobQueue | SQLite/pgboss 同一接口 | pending_browser_ops + setInterval | 抽象待云端形态需要时再做 |
| 向量库 | sqlite-vec / pgvector | 内存余弦 + JSON 存储 | 单用户千级条目足够，无外部依赖 |

## 3. 系统架构

**当前交付：形态 B 单容器自建端**。扩展经 HTTP + Bearer Token 连服务端；服务端进程内同时承担 API、定时任务、公开站渲染、静态托管。未连接服务端时扩展仅 D18 受限离线能力。

```
[扩展 SW/popup/newtab/options/welcome/viewer]
        │  /api/v1（Bearer；CORS 白名单；扩展 origin 非生产放行）
        ▼
[Hono API]── store.ts ──[SQLite WAL]
    ├── Pipeline/OrganizeService ── @mf/ai ── LLM 端点（BYOK/env/mock）
    ├── SemanticService（内存余弦）/ SiteAnalysis（投影缓存入 prefs）
    ├── setInterval 调度（维护 + 收纳盒清扫，同受 MF_MAINTENANCE_INTERVAL_HOURS 门控）
    ├── pending_browser_ops（扩展轮询消费：move/remove/reorder）
    ├── hooks.ts（出站 Webhook，HMAC + 退避 ×3）
    ├── guardedFetch（crawl/favicon/死链共用出站守卫）
    └── /s/:slug 公开导航站 + web-dist 静态托管
```

📋 形态 A（云 SaaS：Postgres + S3 + pgboss + 独立 Worker、多用户）与形态 C（纯本地：IndexedDB + BYOK 直连 + 静态 HTML 导航导出）仅为架构预留，代码不存在。

## 4. 数据模型

SQLite 单库；全部 DDL 在 `apps/server/src/migrate.ts`（MIGRATIONS 数组，v1–v9，启动时 migrateWithBackup，每版本独立事务，只前进不回滚）。

### 4.1 表清单（v9 现状）

| 表 | 用途 |
|---|---|
| `folders` | 目录树（parent_id/name/sort/source/is_system_inbox）；收纳盒是系统目录，不可改名/删除 |
| `bookmarks` | 主表：url_raw/url_canonical（UNIQUE）/title/description/status(normal/dead/suspect/archived)/site_type(site_tool/site_ref/content/NULL)/favicon_url/pinned/added_at/last_checked_at/suspect_streak/last_fail_reason/archived_into/content_revision/is_private/url_key_version |
| `content_cache` | L1 摘要/标签/关键词/L2 正文(≤20k)/lang/embedding(JSON)/fail_reason/fetched_via |
| `material` | 资料库条目（D61/v10）：bookmark_id UNIQUE（FK 级联）/type(article/video/image)/status(active/dismissed)/cover_path+mime+size+url（文件在 DATA_DIR/materials/）/meta/signals(JSON)；正文摘要不复制，读时 JOIN content_cache |
| `domain_cache` | 域名→分类缓存（F1.4 即时建议） |
| `organize_version` | 整理版本：动作 JSON、kind(apply/undo)、reverts_version_id、reverted（回滚安全面） |
| `organize_session` | 整理会话：消息、base_state/base_revisions、status、version 关联（崩溃重试幂等） |

| `changes` | 变更日志（/sync/push、/sync/apply、/sync/pull 游标增量；D49 补齐 updateBookmark 的 title/pinned 改动入日志，浏览器才收得到改名/置顶） |
| `snapshot` | MHTML 元数据（文件在 DATA_DIR/snapshots/<id>.mhtml；via/大小/版本） |
| `pending_snapshot_deletions` | 快照文件删除失败台账（隐私清理重试） |
| `privacy_domain` | 隐私规则（内置 6 条 + 用户自定义；revision 随变更递增） |
| `nav_site` / `nav_site_folder` / `nav_site_bookmark` | 导航站配置（slug/模板/password_hash/config/published/revision）+ 显式发布集合 |
| `tokens` | 管理员令牌：仅存 SHA-256 摘要 + token_id + 过期/撤销/最后使用 |
| `changes` | 同步变更日志（游标） |
| `maintenance_report` | link_check / duplicate_scan / url_key_migration 等报告 JSON |
| `prefs` | KV：notifyStyle、organizeRules、nav_projection 缓存等 |
| `provider_config` | BYOK：base_url/用途模型/api_key 密文（AES-256-GCM） |
| `settings` | KV：admin_password_hash（scrypt）等 |
| `hook` | 出站 Webhook（events/granularity/secret/enabled） |
| `device` | 设备注册（deviceId ≥8 字符） |
| `bookmark_identity` | (device_id, browser_bookmark_id) ↔ app 书签 id（联合主键） |
| `pending_browser_ops` | 浏览器镜像队列：op(move/remove/reorder)/payload/status(pending/done/failed/cancelled)/attempts；终态原因 superseded_by_undo / superseded_by_requeue / sync_delete_disabled / **superseded_by_full_sync**（D49 开总开关后 move/reorder 让位引擎） |
| `inbox_state` | 收纳盒状态机：pending/classifying/placed/ambiguous/privacy_hold/retry/no_llm |
| `bookmark_click` | 应用内点击计数（新标签页"最常访问"数据源） |
| `audit_log` | 操作审计（D58）：kind/detail/source/created_at；认证（登录三态+setup）/令牌撤销/配置变更（供应商·偏好·Webhook）/导航站发布下线；detail 一行摘要，绝不落密码与令牌；保留最近 1000 条 |
| `schema_migrations` | 迁移水位 |

设计要点：
- 无 tag 表（标签在 content_cache.l1_tags JSON）；无 FTS5 虚表（全文=LIKE）；无 job/job_run/usage 表（旧文档虚构）。
- URL 键**保守规则 v2**（D22）：保留 scheme/www/fragment/端口/业务参数，仅删 28 个经验证 tracking 参数，剥 userInfo，路径编码归一+去尾斜杠；similarKey 仅供疑似建议。
- merge = 软归档：被合并方 archived_into 指向保留方（added_at 最早、平局 id 字典序决胜），缓存/快照/私密位全保留。
- 整理动作：move / createFolder（plannedFolderId 映射）/ merge / markPrivate；rename 类型预留无产生点。

### 4.2 迁移版本

v1 基线 17 表 → v2 软归档/乐观锁/会话基线 → v3 设备身份+镜像队列 → v4 保守 URL 键重算（出迁移报告）→ v5 导航显式发布集合（存量站点转待确认）→ v6 令牌摘要化（旧 bearer 失效）→ v7 undo 版本+快照删除台账 → v8 site_type/nav config/hook/inbox_state/bookmark_click → v9 audit_log（D58 操作审计）→ v10 material（D61 资料库；启动时一次性存量回灌，prefs 记完成位）→ v11 material.category（D65 资料自有 AI 两级分类；backfillCategories 涓流回灌常驻）。

**保留裁剪（D58，常驻不依赖调度开关）**：`startRetentionPrune`（maintenance.ts）启动即跑 + 每日一次——changes 14 天（离线设备漏拉由 treesDiffer catch-up 全量对齐兜底）、events 90 天、idempotency 7 天、audit_log 最近 1000 条。

**L1 摘要兜底补扫（D63，常驻不依赖调度开关）**：`startSummaryBackfill`（maintenance.ts）启动即跑 + 每 30 分钟一次——候选=有正文（≥40 字）缺 L1 且失败原因非 `privacy_*`（`llm_unavailable`/`stale_policy_discarded` 可重试）；每次最多 5 条涓流踢 `maybeSummarize`（内部现行隐私判定兜底）；无 LLM 配置零开销跳过。兜住 fire-and-forget 摘要的两类永久缺失：进程重启丢在途、LLM 当时不可用。

**备份**：仅在有待应用迁移时执行——`VACUUM INTO` 输出 `DATA_DIR/backups/pre-migrate-v<n>-<ts>.db`（失败兜底 checkpoint+文件复制）。**无定时备份任务**（旧文档所称"内置定时 VACUUM"不实）；设置页展示备份分片用量、保留约 14 份。

## 6. 浏览器扩展架构（MV3）

**manifest 权限**：`bookmarks, activeTab, contextMenus, storage, unlimitedStorage, scripting, tabs, pageCapture`；命令仅 quick-save（Ctrl/⌘+Shift+S）；host_permissions 只固定 localhost:3000/:3007（云端/NAS 由用户填地址，📋 optional host 动态申请未见实现）。无 sidePanel/offscreen 权限。

**MV3 对策**：SW 被杀死靠 bookmarks 事件唤醒 + storage 持久队列（mfPendingOps、镜像 ops 服务端确认才出队）；activeTab 点击瞬间注入，避免全站 host；SW 内消息路由全程 try/catch 回包。

**关键模块**：
- `lib/api.ts`：ExtensionConfig（serverUrl 默认 127.0.0.1:3000、token、notifyStyle、inboxParent、syncDeleteToBrowser 等）、Bearer fetch、埋点白名单、DTO。
- `lib/device.ts`：mfDeviceId UUID + /devices/register；镜像 ops 执行（move 入 mf-整理；reorder 按实际父节点分组就地排序不搬家；remove 仅删叶子、开关关时回执 cancelled）；空壳文件夹清扫。
- `lib/privacy.ts`：规则本地缓存四态 unknown/fresh/stale/error（24h，按服务端 origin 隔离），仅 fresh 放行五动作，未加载一律保守拒绝。
- `lib/import.ts`：书签树扁平化（跳虚拟根、仅 http(s)、标题截 200、深度 ≤16）。
- popup 单面化（D46）：无页签；收纳盒状态条目内联处理；详见产品.md §7.2。
- newtab/widgets：§7.3 同产品文档；取数在 src/widgets/fetchers.ts（IP 四源/天气双源/TTL 缓存，零新增权限）。

## 8. 关键流程

1. **收藏即时归位**：popup 隐私判定 → /bookmarks/suggest（域名缓存+规则）→ 命中显示目标目录；落库 → 异步 /content/capture → 摘要/向量化后台执行。
2. **收纳盒两阶段**：规则阶段即归位（事务 A）→ LLM 阶段事务外计算 → 提交事务 B（重查隐私 revision/私密/归属，过期丢弃 stale_*）；歧义（阈值 0.6/0.8）留箱内联处理；审核拒收二分隔离（MAX_ISOLATE_CALLS=12，单条仍拒→markPrivate）。
3. **首次导入两阶段整理**：ingest → 阶段 1 规则引擎直接生效（0 token，welcome 展示 Aha）→ 阶段 2 后台抓正文/摘要/embedding/LLM 精修。
4. **整理 act + undo（D27）**：计划→apply 单事务（逐项 commitCheck：存在/revision/隐私/目标/inbox 归属；冲突原因码）→ 写 organize_version + 镜像同事务入队；rollback 逆放生成 undo 版本，后改项跳过，反向镜像入队、旧 pending 取消。
5. **浏览器镜像三操作**：move（任何服务端移动，目标 mf-folder:<名>）/ remove（仅删除且仅身份映射命中，D44）/ reorder（管理台顺序快照，D45）；扩展轮询执行+回执；撤销同事务取消旧单。
6. **收藏夹双向直接同步（D49）**：扩展 sync.ts 引擎——每 tick 拉 /sync/pull（库→浏览器逐条应用 + 按库顺序重排受影响目录）→ diff 基线快照推 /sync/apply（浏览器→库幂等落库）→ 重存快照；触发 = 开关首开全量对齐 / **SSE 门铃秒级（D50，/events/stream fetch 流式消费 + 3s 防抖）** / alarms 1min 兜底（manifest 补 alarms 权限）/ 书签事件 8s 防抖 / 手动立即同步。基线快照即合并点，幂等可重放，冲突后发生效；**基线=上一基线+引擎动作增量维护（非重扫覆盖），末尾 treesDiffer 探测窗口期用户改动 → 5s catch-up 补轮（D53，修「tick 期间删除被吞」）**；开关开启时镜像 move/reorder 回执 superseded_by_full_sync 让位引擎、remove 由引擎接管；单轮任一侧删除 >30 且 >20% 挂保险丝待确认。**系统收纳盒整体豁免**（D51：is_system_inbox 目录不参与补位/放置/重排/upsert-move；mergeDuplicateInboxFolders 自愈旧版误建的重复壳——引擎跳过的子树，放置侧必须同步豁免）。
6a. **虚拟顶层穿透（D55）**：walkBrowser 对书签树第一层无条件穿透（shared VIRTUAL_BOOKMARK_ROOT_TITLES 定义 Chrome/Edge 中英文虚拟名，深层同名合法），路径匹配以用户真实文件夹为零点；pruneEmptyMirrorFolders 附带清理浏览器顶层虚拟名空壳——防止再把「收藏夹栏」当用户目录复制建树。
6b. **目录树删除（D56）**：浏览器删目录 → 引擎对最顶层被删目录发 folder.deleteTree，服务端 store.deleteFolderTree 子优先递归删「子目录+全部子书签+本目录」（事务原子、系统收纳盒拒绝、发起设备不回程 remove）；目录内书签不走逐条 delete；目录级独立保险丝（被删目录 >3 且 >基线 50% 才挂起），区别于散点书签删除保险丝。
6c. **收纳盒自动分类兜底（D57）**：丢入触发即时 flush（1.2s）之外，新增独立 mf-inbox-sweep alarm（1min，不依赖同步开关）→ maybeSweepInbox（/inbox/count 门控，count>0 才 flushInbox），SW 启动补扫；防即时 flush 因 MV3 SW 被杀/超时静默失败致条目永卡 pending。
6. **快照**：扩展 captureMHTML（失败仅元数据）→ message/rfc822 上传 → 查看时 MHTML 解析+白名单清洗+CSP。
7. **资料库物化（D61）**：识别=shared `classifyMaterialKind` 纯规则（图片直链扩展名→image；视频站 host+路径守卫→video；其余 article 兜底）；入库=material 覆盖式 upsert（文章须 l2≥200 字，视频/图片凭 URL 即时入库；隐私域/私密/回环 127.0.0.1 永不入库）；封面=og:image（扩展捕获上行）或图片 URL 本体，server_fetch 隐私判定前置后 guardedFetch 下载（2MB 上限+魔数嗅探，非图片拒绝），落 DATA_DIR/materials/<id>.<ext>；启动回灌一次（纯本地零网络）；dismiss 软删防复活；对外导出=Markdown。
7. **死链检测**：DNS→HEAD→GET 复验三级；SSE 推送；suspect 连续次数 suspect_streak；隐私域不探测（探测即泄露在册信号）。
8. **出站 Webhook（D33 出站已落地）**：bookmark.added/bookmark.organized/checkup.done；隐私命中永不发；HMAC-SHA256（X-MF-Signature/X-MF-Timestamp）；meta/full 粒度（full 不含正文快照）；1s/4s/9s 退避；异常全吞。📋 入站收藏 API 未做。

## 9. 安全设计

- **隐私不可绕过（红线②）**：五动作校验在 @mf/shared 引擎内；扩展端策略未加载保守拒绝（四态缓存）；服务端调用前校验 + LLM 返回后比对 revision 重验，过期丢弃（stale_policy_discarded）；embedding 前后双验。
- **鉴权两模式**：① 设 ADMIN_PASSWORD → env 密码登录；② 未设且生产语义 → 首启 503，仅放行 /admin/setup（≥8 位密码 + x-mf-setup-token，来源 MF_SETUP_TOKEN 或 /data/bootstrap-token.txt 0600，成功即失效），scrypt 存 hash。dev/test 无密码=全开。
- **令牌**：32 字节随机，仅存 SHA-256 摘要 + token_id，默认 30 天，可按 ID 撤销/logout；列表不回可复用凭据。
- **限速**：内存滑窗 5 次/60s/key（admin-env/admin-db/nav 分 key，MF_TRUST_PROXY=1 才信 XFF）。
- **Key 加密**：AES-256-GCM（scrypt 派生 MF_SECRET_KEY，密文 v1:iv:tag:ct）；生产无 ≥16 字符主密钥保存 Provider 直接报错；列表永远 ********。
- **SSRF 守卫（fetch-guard.ts）**：三模式 cloud/selfhosted_strict（默认）/allowlist；禁段覆盖私网/链路本地/CGNAT/IPv6 ULA 等；DNS 后连接固定校验 IP（防 rebinding）；重定向逐跳重校验+跨主机剥凭据头；字节上限与总超时。crawl/favicon/死链/Hook 共用；管理员配置的 LLM 端点不套 SSRF。
- **可见性边界**：X-MF-Private:1 才可见私密（公开入口永不传）；/content 私密 404；关键词/语义/导出/目录计数同边界；公开站仅显式发布集合内非私密非软归档项。
- **快照**：净化 script/iframe/object/embed/form/外链/on*/javascript:/data: URL，CSP default-src 'none'；无法消毒给下载而非强显；下载 nosniff+attachment。
- **CORS**：MF_ALLOWED_ORIGINS 白名单；非生产额外放行 localhost 与扩展 origin；允许头含 Authorization/Idempotency-Key/X-MF-Private/X-MF-Device。
- **静态托管**：仅 /assets、/brand、/providers + 根 index.html 白名单（path.resolve 防穿越，MIME 白名单，缓存分级）；/favicon.ico 固定 204。
- **日志**：只打方法+路径模板+状态+耗时，不打 query。
